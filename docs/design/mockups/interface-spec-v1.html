02 · 需要人的地方

三级，按"不处理会怎样"分，不按工具类型分。

级别什么情况不处理会怎样提示强度
① 阻塞 ask_operator：生产库、敏感数据、写操作。agent 停在那里等。 永远等下去。这一档没有超时兜底，因为自动填一个假结果比等着更糟。 实心暖色标头 + 顶栏计数 + 窗口 dock 角标。列表永远置顶。
② 限时 canUseTool 闸门：范围过宽、动作可疑、方向不对。 倒计时归零后按预设放行，节点上标"自动放行"。 暖色描边 + 倒计时环。环走完前有声音以外的一切提示，但不抢焦点。
③ 告知 只读类调用已自动放行。 什么也不会发生。 折叠成一行计数，中性色。展开才看得到明细。
暖色是全局唯一的。 界面里除了"需要人动手"，任何地方都不用暖色。这样余光扫过屏幕时， 有没有事找你是一个颜色的有无，不需要读字。
① 档的四个字段有固定顺序：语句 → 预期 → 执行时间 → 结果。 预期排在结果之前是硬要求（挡住"看到数据再倒推一个说法"）； 执行时间不能省，它是这条证据进事故时间线的唯一凭据。
键盘要能全程处置。 ↵ 提交回填 · A 放行 · E 改写 · D 拒绝并留话 · J/K 在待办间移动。 切窗口去执行 SQL 再切回来的成本已经很高，不该再加上找鼠标。
批量问是提示词的事，批量答是界面的事。 ① 档同时有多条时纵向排列共用一个提交动作，不要逐条弹。
03 · 视觉

能查清问题排第一，好看排第二。下面这些是硬线。

颜色
语义色只有三个成立 #5A9EDD · 推翻 #C9564C · 需要人 #E0A94A。不再增加第四个。
每个语义色两档描边档用于调查台，正文档（同色相亮一级）用于报告的大字。同一个颜色的两种用法，不是新颜色。
色板全局一套调查台与报告不分深浅两套。差别只能来自密度、字号、留白。
选中不用填色用边框和极淡底色，填色会和语义色打架。
对比度正文对底 ≥ 7:1，次要文字 ≥ 4.5:1。语义色只做标记，不承载正文。
字号下限
正文13px。节点里的假设句是要读的内容，不是标签。
日志等宽11.5px。再小就得眯眼，而这是全屏最需要看清的东西。
全大写小标签9.5px + 0.1em 字距，只用于分区名与状态词，绝不用于内容。
不做的
纹理与扫描线一律不加。它们和日志的等宽字打架，长时间看很累。
装饰性动效只有两处动：进行中节点的状态呼吸、倒计时环。其余不动。
圆角与阴影面板直角、无投影。层次靠 1px 分隔线和底色深浅，密度更高。
图标代替文字状态一律写字（成立 / 推翻 / 等待回填）。图标在截图分享时会失去含义。
密度分层：轨道密、现场疏、待办居中。 轨道是扫视用的，行高压紧；现场是要逐字读的，给足行距； 待办要能一眼看到边界，用分隔带切开。
04 · 结案后

报告是单列长页。没有 tab，没有折叠，没有内部滚动。

这条不是审美偏好，是被长图导出倒逼出来的：凡是要靠点击才能看到的内容，截图里就不存在。 所以顶部那条是锚点导航——点击只滚动，不隐藏任何东西，导出时整条被移除。

报告与调查台共用同一套色板——底色、语义色、字体全都一样。 两个界面的差别全部来自密度与字号：调查台是拿来操作的，要密；报告是拿来读的，要疏。 靠色相分工会让人以为打开了另一个应用。

操作界面要密，阅读界面要疏——这个差别不该由色相来承担。 一深一浅会读成两个应用，而这是同一个工具的两个阶段： 报告里那句根因，和调查台里 ST3 的判定，本来就该是同一个东西。
竖线 + 圆点是两个屏共用的母题。 调查台的轨道和报告的事故时间线都用它，只是含义不同：轨道上是"我按什么顺序做的"， 报告上是"系统当时按什么顺序发生的"。同一个形，两条不同的线——这正好是本工具最核心的那组区别。 关键事件的圆点填实，其余空心。
语义色在两个界面各有深浅两档。 调查台上它多做描边（#5A9EDD），报告里它更多直接当正文色， 因此用同色相的亮一档（#82B7E8）。这不是第四个颜色，是同一个颜色的两种用法。
打印是唯一的例外。 深色页打印要么费墨要么被浏览器反色。这由 @media print 单独处理—— 换纸不换设计语言，和屏幕、图片是三种介质的事。
05 · 导出之一

Markdown：给会被继续编辑、被搜索、被贴进 PR 的场合。

根因用引用块置顶很多平台的预览只显示前几行，第一屏必须是结论本身。
时间线用表格，不用 mermaidmermaid 在不少 wiki 和评论区不渲染，一旦不渲染就是一团噪音。mermaid 放进末尾的 <details> 作为附加。
证据用脚注正文只留 [^e9]，工具、锚点、时间戳来源统一落在文末索引。正文因此保持可读。
被推翻的用删除线删掉就成了"一路顺利"的假历史。
空的遗留疑点也要写写「无」比整节消失可信。
不用 HTML 排版除了那个 <details>，全篇纯 Markdown，保证到处都能渲染。

06 · 导出之二

长图：给一贴进群里就要被看懂的场合。

长图不是"报告页的截图"，是报告页的另一个渲染视图（?export=image）。 它和屏幕视图共用数据与样式，但去掉一切交互件。

规格
宽度1240 CSS px，@2x 输出 2480px。手机上看清楚的下限。
去掉锚点导航条、导出按钮、"展开全文"、任何 hover 才出现的东西。
日志片段只保留命中行 ±3 行并高亮；完整原文只在 app 和 Markdown 里给。
页脚水印每页固定：Case 编号 · 生成时间 · 「17 条证据可在 Inquestry 溯源」。
分页超过 6000 CSS px 时按顶层小节切，绝不从小节中间切断。每页页眉带「Case 0417 · 2/3」。
配色与报告页一致的深色，所见即所得。图片是这个工具的名片，不该长成另一副样子。
不跟随系统主题导出结果必须可预期：同一个 case 在谁的机器上导出都是同一张图。
这条约束反过来改了报告页的信息架构。 既然图片里点不动，报告页就不能有 tab、折叠面板、内部滚动区。 所有块必须平铺在一条纵向流里——上面那张报告 mockup 已经按这条做了。
实现路径
离屏窗口新建 BrowserWindow({show:false, width:1240}) 载入导出视图，读 scrollHeight 后 setContentSize，再 capturePage。
必须等两件事document.fonts.ready 与一帧 requestAnimationFrame。已知 capturePage 会返回过期帧，未获焦点的窗口尤其容易——不等就会拍到半成品。
校验拍完比对图片高度与预期 scrollHeight，不符就重拍一次再报错，别默默产出半张图。

中途插话的四种方式
方式语义落到哪
底部输入带 异步入队，不打断——"我不拦你，这轮收尾时看一眼" 轨道插入一个「补充」标记节点，可撤回
选中某个节点再说 同上，但消息带 step 引用——"你第 3 步的前提是错的" 补充挂在那个节点下，比全局输入框精确得多
拒绝并留话 deny + message，turn 不中断，就地换方向 该调用记为"被拒"，留话进节点
改写参数后放行 allow + updatedInput——查询写窄了直接改了让它跑 记 input_rewritten，改后的语句一起回传
⚠ 撤回有个粒度坑。 多条排队消息被合并成一个 turn 后，撤回非代表那条是空操作（内容照跑）， 撤回批次代表那条会丢掉整批——两种情况都报"未取消"。 所以 UI 上要么不给批内单条撤回，要么明说"会连同这批一起撤回"。
三种收尾，不是一个按钮
动作对 agent状态之后
停止 中断当前 turn，连排队消息一起清 open 随时新开 session 接着查
结案 先走完影响面与遗留疑点两个强制 step closed 冻结，只能导出
归档 同"停止"，外加标记放弃 aborted 仍可导出残报告
提前终止不销毁任何证据。 这和"结论可以被推翻，事实不会"是同一条原则：停下来时已经采到的东西照样成立。 终止只做两件事——挂起中的 pending 一律改判 abandoned（否则库里攒下永远 resolve 不了的僵尸节点）， 以及给 Case 打上状态。
残报告的形态强制为「未决型」。 主体是排除矩阵与遗留疑点，顶部明写"调查在第 N 步被人为终止"，没有根因栏—— 没查出来就是没查出来，不编。这比一份看起来完整实则半截的报告有用。
08

接下来做什么

按依赖排序。前三项是"日常能用起来"的最小闭环，之后才轮得到把报告做漂亮。

  1. 立案面板

    项目起点 + 问题 + 时间窗口 + 基准日与时区。排在第一位不是因为它显眼，而是因为没有基准日就没有 occurredAt，没有 occurredAt 事故时间线就是空的——现在靠会话上下文兜着，得落到 cases 表。

  2. 待办栏接上两个控制手势

    改写参数再放行、拒绝并留话。控制面唯一还没接的部分。先做 ② 档闸门，再做 ① 档回填。

  3. 案件切换栏 + 全局待办汇总

    多个案子并发跑起来之后，"等你处理"必须跨 case 汇总，否则后台那条支线会静静挂死。同时定活跃 session 的上限与降级策略。

  4. 三种收尾：停止 / 结案 / 归档

    Case 加 aborted 状态；终止时把挂起的 pending 一律改判 abandoned。这条不做，库里会攒下永远 resolve 不了的僵尸节点。

  5. 轨道换成主干 + 分叉

    当前是平铺卡片流。改成定宽画布内的绝对定位，主干只追加、分叉向右缩进，被推翻的节点加回指线。布局不得因新节点而重排。

  6. 加 verdict_shape 与 expected/actual

    schema 增量很小，但决定报告装哪几块。趁历史数据还少赶紧加——这类字段事后补的代价是历史案子全部残缺。

  7. 报告拆成独立屏，改单列长页

    顶部换成锚点导航。这一步做完，长图导出才有可能是对的。

  8. 两个导出

    Markdown 先做（纯字符串拼装，可单测）；长图后做（要处理离屏窗口与字体就绪）。两者共用同一份章节组装逻辑。

  9. Spike A2：子 agent 泳道

    分叉的真实数据来源还没验过——agent_id 与 parent_tool_use_id 是否够用，决定轨道里那两条支线怎么归属。
