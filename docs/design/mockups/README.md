## report-v1.html

2026-08-15 报告页打磨的方案件，**已按它实现**。直接用浏览器打开，无依赖、无构建；底部那条深色控制条是 mockup 自己的，不属于方案（三枚按钮分别是「未收尾 / 已定稿」两态与「对照现在的顶栏」）。

> ⚠️ **形态选择器那一条后来整个被推翻了**（D25 / [ui.md](../ui.md) §8.4.2）：形态改由 agent 声明，人不再选，纸头上只剩一行字说"按哪种装 + 是谁定的"；报告也不再按形态硬丢块，只决定哪一块排最前。稿子里那排按钮与「未决型点一下根因栏消失」的演示因此都不作数了。它是冻结件，不跟着改。

它当时要回答的是一件那会儿的实现答不上来的事：**定稿要选一种报告形态，而那个选择器长在确认条上、选了什么下面这份纸一点都不变**——人在唯一不可逆的那一下上做一个从没预览过的选择。

稿子里试的五条：

- **形态选择器搬进纸头，点一下整份纸当场换装**（未决型那一下连根因栏一起消失）。真实实现里它作为一个可选 node 传进 `ReportPaper`，长图那份不传——控件因此不可能漏进导出，不靠"记得删"
- **报告屏与工作区共用同一条整幅顶栏**，这一屏的动作（就一枚「工作区」）长在它右端，与工作区那两枚同一个位置、同一个样子。报告屏原先自己另起一条页头，于是同一个应用里有两种顶栏，差别一大就读成两个界面
- **锚点从顶栏改成左侧一条吸附的章节栏**，每一节旁边带一行读数（「9 步 · 1 处推翻」），所以它随形态一起变；**交付自成一条轨道**，与章节隔开。样子是一条发丝轨道 + 当前那一段点亮（与报告的时间轴、rail 的当前标记同一个母题），**不填色也不用圆点**：填色会和旁边的语义色打架，而圆点的填实 / 空心在时间轴上已经有含义了
- **两种导出并排两张缩略卡 + 一个导出预览浮层**：卡上是缩略（长图是把这份纸按 1240 真排一遍再缩、Markdown 是前若干行真源码）加尺寸页数，回答"大概长什么样、多大、切几页"；完整那一份进浮层看。那一层不进任何导出，所以不受 D22「报告页不许有折叠」的约束——那一条防的是"截图里没有的内容"
- **定稿 / 归档的二次确认就地展开**在按下去的那个按钮下面，不弹回顶部横幅

⚠️ 两个数字是稿子自己按 DOM 算的、不是真实导出链路的读数：长图的高度与页数、Markdown 的行数与 KB。分多页那一支这份夹具触发不到（它只有 1758px，`PAGE_MAX` 是 6000）。

⚠️ 章节栏的宽与纸宽是一对：`rail + 176 + 1240 = 1468`，窗口窄于这个数纸就先让，屏上的断行与导出的图对不上一点。加宽章节栏等于把这个数往上抬——那行读数放不下才加，不为了好看加（所以每条读数只说一个数，写不下就截）。

🔴 **`scroll` 事件也是帧驱动的**：实测在不获焦点的窗口里一次都不派发，rAF / IntersectionObserver 同族。所以**无人值守探针拍出来的报告屏，章节栏高亮永远停在第一节**——那不是 bug，别去追。点章节栏那条路不受影响，它自己同步算一次。

🔴 **章节栏的"当前节"要单给到底那一档兜底**：末节比一屏矮时它永远顶不到判定线，滚到底了高亮还停在上一节，点最后那一格于是"点了没反应"。而末节正是交付。

它只回答"当时长什么样"。**规格已经落进 [ui.md](../ui.md) §6 与 §8.4.2、[overview.md](../overview.md) §6.3 与 D22，实现以代码为准**；三者有分歧时这份是错的那个。同前几份，不要为了让它跟上代码而去改它。

落地时与稿子不同的两处：稿子里长图卡按 `PAGE_MAX` 自己算了页数，实现里不算——**真实分页只有 main 的离屏窗口量得出来**（`ExportImage.tsx`），在预览里另算一遍必然与真的对不上；同理稿子上那些 KB / 高度读数也没搬。另外补进了 `Icon.tsx` 三个图标：复制、还原、看全。
