## 1. 两个阶段，不是两个 tab

工具有两个形态完全不同的界面，分属两个屏：

| | 调查台（case 屏） | 报告（report 屏） |
| --- | --- | --- |
| 主角 | 假设与分叉 | 判定与证据 |
| 时间轴 | `observedAt` | 由形态决定，未必有 |
| 可操作 | 放行 / 改写 / 拒绝 / 接管 | 只有导出 |
| 刷新 | 每秒都在变 | 结案时冻结 |
| 失败的样子 | 拦不住、看不清在干嘛 | 看完还得问"所以是啥" |

两条时间线是同一批证据的两次投影，这是数据模型的事实，不该翻译成顶栏的两个 tab——排查线属于调查台，事故线属于报告。

**但两个屏共用同一套色板**——底色、语义色、字体完全一样。差别只来自密度与字号：调查台是拿来操作的，要密；报告是拿来读的，要疏。

| | 调查台 | 报告 |
| --- | --- | --- |
| 正文 | 13.5px / 1.6 | 15.5px / 1.72 |
| 判定大字 | — | 26px |
| 页边距 | 14px | 60px |
| 小节间距 | 12px | 44px |
| 底色 / 语义色 | 完全相同 | 完全相同 |

一深一浅会被读成两个应用，而这是同一个工具的两个阶段——报告里那句根因，和调查台里 ST3 的判定，本来就该是同一个东西。

## 2. 调查台：三区

```
┌ 顶栏  案件标题 · 状态计数 ·「N 项待你处理」· 计时/花费 · 接管 · 停止 ┐
│                                                                  │
│  轨道 344px      现场 flex               待办 328px               │
│  走到哪一步      这一步凭什么            哪些事卡在我这           │
│                                                                  │
└ 底栏  对话带（默认只露最后一句）+ 输入框 ──────────────────────────┘
```

**左·轨道**——主干纵向 + 分叉右生长，见 §3。
**中·现场**——当前 step 的假设 / 证伪条件 / 判定，工具调用的原始输出 preview（命中行高亮），以及抽取出的证据行。
**右·待办**——所有需要人动手的事，按紧迫性分三级，见 §4。

对话被压到底部一条带，默认只显示最后一句 assistant 文本。实跑下来看的确实是节点：agent 的文字里已经没有证据搬运，只剩判断，压缩掉不损失信息。

## 3. 轨道：主干永不重排

这是实时图唯一不可让步的约束。

> **主干严格纵向单调追加，永不重排；分叉只向右生长，分叉子树自己也遵守同一条约束。**

理由不是好看，是**新节点每几秒钻出来一个，任何"把图排漂亮"的布局算法都会让已有节点位移**——正读着第 3 个节点的证据，它跑了。代价是图越来越高而不是越来越宽，而纵向滚动本来就自然。

实现上主干 x 固定，分叉整体右移一个缩进量，新节点只能出现在下方或右侧的空白处。x 是算出来的，y 交给文档流（理由见 §3.1）。

**推翻关系用一条曲线回指**：被推翻的节点划掉并标「← 被 stX 推翻」，一条线从推翻它的节点弯回来。**全屏只有这一种曲线，它只表示推翻**——所以它一出现就不用读字也知道发生了什么。

上限约 40 个节点，再多要折叠。折叠规则待真实案子验证后再定。

### 3.1 实现契约

布局本身是纯函数 `src/renderer/track.ts` 的 `trackLayout()`，由 `npm run spike:track` 兜底。

- **只算 x，不动顺序。** 行序逐字是快照给的到达顺序。按树分组渲染看着更整齐，
  代价是一个晚到的分叉子节点会被挪到父的下面，把它和中间那几步已读的主干节点一起推走
- **深度只从已经出现过的父算。** 这一手同时兜掉父在后面才到、父根本不存在、父指向自己三种情形，
  一律落回主干；也因此它天然不会成环，不需要防环。反过来"在整份列表里找父"的写法，
  会在父到达那一刻让早先那一行的缩进跳一格——正是这条约束要禁的位移
- **"认不得的父当主干"这条契约得由写入侧兑现，光在渲染侧兜没用。** `steps.parent_step_id`
  上有开着的外键，`open_step` 把 agent 给的 id 原样发出去的话，手误换来的是
  `FOREIGN KEY constraint failed` + 事务回滚，这一步压根开不出来。所以 `openStep` 先按
  **本案子**核一遍（只核"存在吗"不够：别的案子的 step 过得了外键，却不在这条轨道上），
  认不得就归一成主干并回一条 warning——静默丢掉会让 agent 以为分叉已经记下了
- **序号恒为 `#N`，会话号只出现在跨会话的引用里。** 一度写成"多会话时全部带 `S1#N`"，
  而"是不是多会话"要看整份列表：第二次会话一开，已经渲染出去的每一行都被回头改写一次。
  同理**第一行永远不标会话断点**——标了的话第二次会话一开就要在轨道顶上插进一个块，
  把每一张已读的卡片整体下推。位置、缩进、序号、断点，一个都不许回头改
- **y 交给文档流，不做绝对定位。** 绝对定位的 y 要先量高度，而卡片展开工具调用时高度就变了；
  走文档流则不重排的保证照旧（顺序不动、新节点只在末尾追加），还白得一个自适应
- **缩进封顶**（`MAX_DEPTH`），再深就跑出画布。超了仍然是父子，卡片上标 `⇥`
- **分叉靠缩进 + 「↳ 接 #N」认，不画连接线。** 父与子之间往往隔着几步主干，
  一条从父拉下来的线会横穿那几张卡。留给曲线的独占地位也正是这么来的

推翻回指线是全屏唯一的曲线，走最左边那条空槽（`--track-gutter`）：两头贴着卡片左沿，
而那一带在各自那一行都是空的，所以它不压任何一个字。它得量位置才画得出来，
靠 `ResizeObserver` 跟着卡片走（观察轨道**和每一张卡**——只观察轨道会漏掉"总高没变、位置变了"）。

- **箭头指向被推翻的那一步。** 没有箭头时曲线两头长得一样，得读字才知道谁推翻了谁
- **推翻者不在这条轨道上时（跨案、或还没到），曲线画不出来，但划线和「← 已被推翻」照旧。**
  少一条曲线只是少个指向，少一道划线则是把一个已经作废的结论显示成仍然成立的
- **两种推翻的正文一样中性。** `superseded` 是卡片自己的状态类，
  给「被 X 推翻」徽标写的 `.superseded { color }` 不限定在 `.head` 里就会把整张卡的正文染红，
  而同为推翻的 `refuted` 卡不会——看起来成了两回事

### 3.2 子 agent 泳道就是一次分叉

归属那半在 harness 侧（overview §4.5 / §9.15，桥在 `src/main/lane-bridge.ts`），
轨道这半**一行没改**：泳道的兜底步把 `parent_step_id` 指到起它那次调用所在的那一步，
`trackLayout` 照旧按父子缩进。轨道不认识泳道，也不该认识——它只管"接在谁下面"。

- **缩进说不出「这是另一条 agent 在查」**，所以卡片上另有一枚中性色的「支线 ⟨key 后六位⟩」徽标。
  **不用暖色**：暖色是「需要人动手」的全局专属，一条支线在后台查东西并不找人
- **一条支线可能认不出自己的父**（桥比第一次工具调用晚到时，overview §9.15）。那一行落在主干层，
  但徽标照旧——读的人看得出"这是另一条 agent 在查"，只是不知道接在哪一步。反过来把它当主干显示才是错的
- **支线的兜底步没有 `direction`，但它的空文案与主干那条不一样。**
  主干那句是「agent 在声明方向之前就先查了一次」，支线那句得说清方向由主线收敛时给——
  照抄主干那句的话，读的人会以为主线漏了一次 `open_step`
- **顶栏的「支线 N」与「进行中」是两枚独立的药丸。** 支线默认就在后台跑（overview §3.4），
  主线这一轮收了之后它还可能在查。合成一个的话，界面要么把"只剩支线"说成主线在跑
  （停止按钮跟着冒出来，而它中断的是一轮已经收完的 turn），要么说成空闲
- **一条支线跑完要在对话带上留一句话。** 认 `task_notification` 而不是 `SubagentStop`——
  被人停掉的那条不发后者（overview 附录 A.1），靠它收尾会让那条永远挂着
- **跑完的支线当场收口**（§9.16）：那一步的状态变成「已收口」，正文是**支线自己的话**
  （`SubagentStop` 的最后一句，没有就退回通知里的摘要）。
  收口不是一种判定——那一步没有命题，`已证实` / `已推翻` 都无从谈起，所以它用中性色，
  也不进报告的任何一栏。留着不收的话，一条早就跑完的支线会永远显示成「进行中」
- **「停」长在那一行上，不在顶栏。** 顶栏那枚「支线 N」只说得出还剩几条，说不出要停的是哪一条；
  停一条支线只停它自己（overview §3.4），入口就该在它自己那张卡上。
  **只给还在跑的那几条显示**——停一条已经收尾的支线什么都不会发生，而按钮会让人以为发生了
- **按下「停」不当场收口**：被停掉的支线照样会发 `task_notification`，收口仍走那一条路。
  两处各收一次的话，收口时刻会被按钮那一下提前，后到的通知则什么都收不到

## 4. 需要人的地方：按"不处理会怎样"分三级

不按工具类型分，因为工具类型不决定紧迫性。

| 级别 | 什么情况 | 不处理会怎样 | 提示强度 |
| --- | --- | --- | --- |
| ① 阻塞 | `ask_operator`：生产库、敏感数据、写操作 | 永远等下去。**这一档没有超时兜底**——自动填个假结果比等着更糟 | 实心暖色标头 + 顶栏计数 + dock 角标，永远置顶 |
| ② 限时 | `canUseTool` 闸门：范围过宽、动作可疑、方向不对 | 倒计时归零按预设放行，节点标记"自动放行"（§3.6） | 暖色描边 + 倒计时环，不抢焦点 |
| ③ 告知 | 只读类调用已自动放行 | 什么也不会发生 | 折叠成一行计数，中性色 |

**暖色是全局唯一的。** 界面里除了"需要人动手"，任何地方都不用暖色——余光扫过屏幕时，有没有事找你是一个颜色的有无，不需要读字。

**① 档四个字段的顺序是硬要求**：语句 → 预期 → 执行时间 → 结果。预期排在结果之前挡住事后合理化（D15）；执行时间不能省，它是这条证据进事故时间线的唯一凭据（§5.1②）。语句可改，改后连同结果一起回传给 agent。

**键盘要能全程处置**：`⌘↵` 提交回填 · `A` 放行 · `E` 改写 · `D` 拒绝并留话 · `J/K` 在待办间移动。切窗口执行 SQL 再切回来的成本已经很高，不该再加上找鼠标。

> 提交用 `⌘↵` 不是 `↵`：回填框要能粘多行结果，`↵` 得留给换行（与底部输入带同一个手势）。`J/K` 落到一张①档卡上时直接把光标放进结果框——切窗口跑完 SQL 回来，下一个动作一定是粘贴。代价是此时单字母键归输入框所有，要用 `A/E/D` 得先 `Esc` 或点开别处。

**① 档同时有多条时纵向排列共用一个提交动作**，不要逐条弹——批量问是提示词的事，批量答是界面的事（§5.1③）。

## 5. 视觉纪律

能查清问题排第一。下面是硬线。

| | |
| --- | --- |
| 底色是四阶冷灰蓝，**不用纯黑** | `#0E1317` 代码块 / `#141A1F` 应用底 / `#1A2128` 面板与顶栏 / `#212A32` 选中。纯黑上的白字会晕，长时间看更累 |
| 语义色只有三个 | 成立 `#5A9EDD`（蓝，主色） · 推翻 `#C9564C` · 需要人 `#E0A94A`。不加第四个 |
| 每个语义色两档 | 描边档给调查台，正文档（同色相亮一级，如 `#82B7E8`）给报告的大字。同一个颜色的两种用法，不是新颜色 |
| **蓝底不配黑字** | 深色界面里蓝色填充块必须配浅字：底压到 `#2A6598`、字用 `#F2F8FD`。琥珀是例外——它本身够亮，配深字 `#1A1206` 才对 |
| 色板全局一套 | 调查台与报告不分深浅两套，差别只能来自密度、字号、留白（§1） |
| 选中不用填色 | 用边框 + 极淡底色，填色会和语义色打架 |
| 对比度 | 正文对底 ≥ 7:1，次要 ≥ 4.5:1。语义色只做标记，不承载正文 |
| 正文字号 ≥ 13px | 节点里的假设句是要读的内容，不是标签 |
| 日志等宽 ≥ 11.5px | 再小要眯眼，而这是全屏最需要看清的东西 |
| 全大写小标签 9.5px | 只用于分区名与状态词，绝不用于内容 |
| 不加纹理与扫描线 | 和等宽字打架，长时间看很累 |
| 只有两处动效 | 进行中节点的状态呼吸、倒计时环。其余不动 |
| 直角、无投影 | 层次靠 1px 分隔线与底色深浅，密度更高 |
| 状态一律写字 | 不用图标——截图分享出去时图标会失去含义 |

密度分层：轨道密（扫视用，行高压紧）、现场疏（逐字读，给足行距）、待办居中（要一眼看到边界，用分隔带切开）。

## 6. 报告页

单列长页，**没有 tab、没有折叠、没有内部滚动**。

这不是审美偏好，是被长图导出倒逼的：**凡是要点击才能看到的内容，截图里就不存在**（§7.2）。顶部那条是锚点导航——点击只滚动，不隐藏任何东西，导出时整条移除。

章节由形态组装，见 [overview](overview.md) §6.1.1。每节右侧标注数据来源（`投影 · ORDER BY occurred_at_ms` / `agent 生成`），让"哪些是投影、哪些是生成"对读者可见——这把 D17 变成用户能验证的承诺。

被推翻的 step 强制留在「排查路径」里（划掉 + 标注），不洗成一路顺利的叙事。

**事故时间线画成真正的时间轴：一条竖线 + 圆点**，关键事件的点填实、其余空心。这和调查台轨道是同一个母题，只是两条线的含义不同——轨道上是"我按什么顺序做的"（`observedAt`），报告上是"系统当时按什么顺序发生的"（`occurredAt`）。同一个形承载两条线，正好是本工具最核心的那组区别（§1.4）。

竖线只在时间轴内部出现，与 §3 那条"全屏唯一的曲线表示推翻"不冲突：一个是直线连接、一个是曲线回指。

### 6.1 实现契约

章节的组装是**纯函数** `reportPlan()`（`src/shared/report.ts`），报告屏与两种导出共用它——写两遍的必然结果是导出的那份和屏幕上的那份对不上，而报告是这个工具唯一交出去的东西。Markdown 那一侧的渲染在 `src/shared/markdown.ts`（§7.1）。由 `npm run spike:report` 与 `npm run spike:markdown` 兜底（夹具是同一份 `scripts/fixtures/report-case.ts`），**改这一带之前先跑这两条**。

导航那一条上除返回外只有两个导出按钮（「导出 Markdown」「导出长图」）。**两种导出并列一等（D26），长一个样**——把其中一个做成次要按钮就等于替人选了一种。导出的回执（成功的路径 / 失败的原因，分页时还有共几张）贴在导航下面。这些都是交互件，长图视图里不会有它们。

- **「不投影」那一列与「主体块」同样是规则。** 这一带的错法只有一个形状：*有数据就装*。它一条都不报错，装出来的报告看着还更完整——归档强制未决型，而被归档的案子多半已经查出了点什么，按"有就装"写的话，明写着"没查出来"的残报告会顶着一条根因。时序型印上应然/实然、分布型补一条时间线，都是同一个错
- **同一节在一份报告里只出现一次，位置以先出现的那次为准。** 遗留疑点在未决型里是主体块、又在通用四块里；不去重就印两遍，去重时留错那一份则会把主体挪到末尾
- **报告屏不自己挑根因。** 选择器只有 `queries.reportSections()` 那一条，`rootCause` 连 `stepId` 一起进快照。再挑一次的后果是因果链标的根因与根因栏印的结论指着两步，且毫无报错（与 §8.4.2「取哪一步的声明」同源）
- **通用四块永远在，空的写「无」。** 整节消失读起来像"没这回事"，写「无」才是"查过，没有"
- **没收尾时报告是预览**：形态取 `shapeSuggestion` 并在页首说明它还会变；收尾之后只认冻住的 `verdictShape`，推断值不再参与——那是人在确认条上按下去的判断，事后没有入口再改
- **时间轴的点填实 / 空心区分的是「这条证据出自的判定还成不成立」**，被推翻那一步给的证据照旧在列（结论可以被推翻，事实不会）。§6 原话写的是"关键事件填实"，但库里没有"关键"这个标记，不编一个
- **归因切分按证据的 `actor` 归组**，取的是全部证据而不是事故时间线那一份——"只在某一小撮上"与有没有时间戳无关，按时间线算会凭空少掉一组
- **因果链在根因那一步收束。** 根因之后那些已证实的结论是另一件事，不截断的话根因会出现在链条中间，而这一节的整个意思就是"一路推到这里"。它们没有丢，排查路径那一节照旧全列
- **编号跨会话要带会话号**（`S2#1`）。`ordinal` 是会话内序号，重开一次就从 1 重来；直接印的话报告里会有两个 `#1`，「← 被 X 推翻」这类引用也就无处可对。**所有对 step 的引用都走同一张 `labels` 表**，别在某一处直接印 `stepId`。报告是冻住的文档，不受 §3.1 那条"序号不许回头改写"的约束——那一条防的是实时图里已读节点位移
- **页脚的证据数是全案证据数**，不是事故时间线的条数（后者只留了带时间戳的那些，拿它当总数会把证据量报少）
- 🔴 **别用吃帧循环的东西做落点或度量。** 锚点跳转一度用 `scrollIntoView({behavior:'smooth'})`，让开 sticky 导航一度用 `ResizeObserver` 预先同步高度——**两者在未获焦点的窗口里都一次都不跑**（同 §11 那条过期帧），前者是点了纹丝不动，后者是留下一个悄悄过期的偏移量，都不报错。现在是点击那一刻同步量导航高度再算落点，全是同步布局读数

## 7. 两种导出，同一份章节组装逻辑

只是渲染目标不同。

### 7.1 Markdown

给会被继续编辑、被搜索、被贴进 PR 的场合。

- **根因用引用块置顶**——很多平台的预览只显示前几行，第一屏必须是结论本身
- **时间线用表格，不用 mermaid**——mermaid 在不少 wiki 和评论区不渲染，一旦不渲染就是一团噪音。mermaid 放进末尾 `<details>` 作为附加
- **证据用脚注**——正文只留 `[^e9]`，工具 / 锚点 / 时间戳来源统一落在文末索引，正文因此保持可读
- **被推翻的用删除线**——删掉就成了假历史
- **空的遗留疑点也要写**——写「无」比整节消失可信
- **除那个 `<details>` 外全篇纯 Markdown**，保证到处都能渲染
- 时间轴的竖线圆点画不进 Markdown，这里退化成表格——这也是长图存在的理由之一

#### 实现契约（`src/shared/markdown.ts`，由 `npm run spike:markdown` 兜底）

渲染纯函数，吃 `reportPlan()` 的输出。**装哪几块、什么顺序一处都不重写**，长图将来吃同一份。

| 约束 | 写错的后果 |
| --- | --- |
| **装不装根因只认 plan** | 渲染侧一句 `if (report.rootCause)` 就让明写"没查出来"的残报告在第一行印上一条根因（库里往往正躺着一条已证实的） |
| **mermaid 只在 plan 真的装了时间线时才给** | 形态说不投影时间线（状态型 / 分布型），从这条侧门塞回去等于让「不投影」那一列在导出里失效 |
| **每条证据都必须在正文里被引到** | 多数渲染器只渲染被正文引用过的脚注定义：漏引一条，那条证据在文档里整条消失，而页脚仍写着「N 条证据可溯源」。完备性挂在**排查路径**那一节（通用四块里唯一"所有 step 都在"的） |
| **进单元格先转义 `\|`、折掉换行** | 一个 `|` 凭空多切一列，一个换行把一行拆成两行，后半行还会被渲染成正文 |
| **竖线前那串反斜杠要一起转义** | 内容本来就带 `\|`（日志、路径、正则里很常见）时，只转义竖线会得到 `\\|`：渲染器先把前两个还原成一个字面反斜杠，后面那个竖线照旧切列 |
| **内容里的 Markdown 元字符一律转义**（`\` `` ` `` `*` `[` `]` `<` `>` `~`，`inline()` 是唯一的转义点） | 内容全部来自 agent 与工具输出，在界面上只是纯文本，进了 `.md` 就被当语法解释，几种后果各不相同：`<img onerror=…>` 在允许 raw HTML 的渲染器上是注入 · `![x](http://…)` 让读报告的人替攻击者拉一次外链（追踪像素），链接文字还能伪造去处 · 反引号从代码块里逃出去 · **`~~…~~` / `**…**` 在这份文档里有语义**（划掉 = 判定被推翻、粗体 = 根因 / 最弱一环），伪造得出来就等于伪造结论 · `[^e1]` 伪造一条脚注引用指到别人的证据上。**`\` 必须第一个换**，否则新加的反斜杠被自己再转一遍。**我们自己那个 `<details>` 与所有排版记号都是代码里的字面量，不走这条路** |
| **`_` 故意不转** | CommonMark 里被字母数字夹住的下划线开不了强调，而 `req_id=abc` 这类日志文本在本工具里满屏都是——转了之后满篇 `req\_id`，换来的只是挡住一种纯装饰性的斜体。已拿真实导出的原文验过：那份报告转义后一个反斜杠都不多 |
| **溯源字段一个字符都不能改**（时间戳 / 锚点 / 工具名） | 它们是读者回查原始日志的依据：锚点 `` foo`bar `` 删成 `foobar` 会指到另一行，syslog 的 `Aug  7 03:04:05` 折掉一个空格就按不着原文。**只把换行折成空格**（表格行与脚注定义都按行来，这一条是被格式逼的），其余一律原样 |
| **文末索引里用 code span：加长围栏，不转义也不删**（`codeSpan()` 返回整段，调用方不再自己包反引号） | 代码块里反斜杠不是转义符（转了会既撑破代码块又留个可见的 `\`），所以只能靠围栏：**取比内容里最长那串反引号多一个**。内容顶着反引号或空白时两侧各垫一个空格——前者不垫会与围栏连成一片，后者不垫会被 CommonMark"首尾各去掉一个空格"吃掉。整段都是空白时反而不垫（那条规则此时不生效） |
| **值进表格用普通文本转义，不用 code span**（`valueCell()`） | 表格里的竖线**连在代码块里也会切列**（GFM 先按竖线切单元格再解析内容），而代码块里反斜杠是字面量、没法拿它转义——于是"要么表格走形、要么值里多出反斜杠"两头堵。换成普通文本就没有这个两难：`\\` 与 `\|` 都是正经转义，渲染回来一字不差，且在"切单元格只认 `\|`"与"先按通用反斜杠配对算"两种读法下结果相同。代价只是这一格不再等宽——拿一格字体换"时间戳与文末索引里的同一个值对不上"，不值 |
| ⚠️ **表格单元格首尾的空白留不住** | GFM 本来就会把它吃掉，这是格式的限制不是我们的选择。所以**文末索引才是溯源那一份**（§7.1 原话：来源统一落在文末索引），表格是给人读的 |
| **内容占满一整行时挡掉行首记号** | 影响面那一节整段就是内容：以 `#` 开头会变成一级标题、`-` 开头变列表。⚠️ `1.` 要转的是那个点——反斜杠加数字在 CommonMark 里不是转义，会留下一个多余的反斜杠 |
| **我们自己排的编号不走内容那条路** | `#1` 过一遍行首守卫会变成 `\#1`，时间线每一行的出处列都带一个多余的反斜杠 |
| **mermaid 标签里剥掉 `"`** | 引号标签里再出现一个 `"` 直接截断节点，整张图渲染失败——而正文那张表看不出问题 |
| **生成时间由调用方给** | 自己读时钟的话同一个案子导两次的产物不同：既没法 diff 两版报告，也没法拿检查兜住页脚 |
| **`—— ` 这类占位来源不印** | 状态型那节"没有来源"，照印会得到一行 `*来源：——*` |
| **索引里说得出"没有"** | 无锚点 / 无时间戳 / 认不出那次调用都要写出来。留空读起来像"这条证据没记全"，而它们都是确定的事实 |

回执与失败：导出走 main（那边才有库与文件系统，且**由 main 拿它自己那份快照渲染**——界面那份最多晚 60ms）。`ExportResult` **把取消与写盘失败分开**：只回 boolean 的话，界面对"人自己按了取消"和"报告压根没落地"只能给同一句话。回执留在屏上不闪一下就没——路径要能被读出来、复制走。

**`invoke` 自己 reject 那条路也要接**（main 抛了、通道关了）：只有 `finally` 没有 `catch` 的话，屏上什么都不说、控制台多一条未处理的 rejection，而人看到的与"按了取消"一模一样。这一带承诺的是"所有失败路径都有可见回执"，漏一条这句就不成立。

### 7.2 长图

给一贴进群里就要被看懂的场合。它不是报告页的截图，是报告页的另一个渲染视图（`?export=image`），共用数据与样式，去掉一切交互件。

| | |
| --- | --- |
| 宽度 | 1240 CSS px，@2x 输出 2480px |
| 去掉 | 锚点导航、导出按钮、"展开全文"、任何 hover 才出现的东西 |
| 日志片段 | 只保留命中行 ±3 行并高亮；完整原文只在 app 与 Markdown 里给 |
| 页脚水印 | 每页固定：Case 编号 · 生成时间 ·「N 条证据可在 Inquestry 溯源」 |
| 分页 | 超过 6000 CSS px 按顶层小节切，**绝不从小节中间切断**，页眉带「Case 0417 · 2/3」 |
| 配色 | 与报告页一致，所见即所得。图片是这个工具的名片，不该长成另一副样子 |
| 不跟随系统主题 | 导出结果必须可预期：同一个 case 在谁的机器上导出都是同一张图 |

**打印是唯一的例外。** 深色页打印要么费墨要么被浏览器反色，由 `@media print` 单独处理——换纸不换设计语言。屏幕、图片、纸是三种介质，只有最后一种需要单独一套。

**单页优先。** 多数案子应该压得进一张图；分页是超长时的退路，不是默认形态。如果经常分三页，说明该收的是内容不是尺寸。

#### 实现契约（`main/index.ts` 的 `exportImage()` + `renderer/ExportImage.tsx`，分页由 `npm run spike:image` 兜底、拍照由 `INQUESTRY_EXPORT_IMG` 探针兜底）

离屏 `BrowserWindow({show:false, width:1240})` 载入 `?export=image` → 那一屏按真实排版分页、量出每页矩形 → main 逐页裁图写盘。**正文的渲染是 `renderer/ReportPaper.tsx` 那一份**，与报告屏共用组件，不只共用 `reportPlan()`。

| 约束 | 写错的后果 |
| --- | --- |
| **@2x 由 CDP 的 `deviceScaleFactor` 给，不用 `capturePage()`** | `capturePage()` 的倍率跟着当前显示器走：在 @2x 屏上开发会看到正好 2480px 宽、以为成了，而 1x 机器上悄悄少一半分辨率。「同一个 case 在谁的机器上导出都是同一张图」是这一条的前提 |
| ⚠️ **attach 与 `Emulation.setDeviceMetricsOverride` 必须排在载入之后** | 对着还没载入文档的窗口发 CDP 命令，**整个进程 SIGSEGV**（Electron 43 实测）。表现极难认：main 直接没了、一行日志都没有、退出码还是 0，看起来像那段代码压根没跑 |
| **`fromSurface: true`，`clip.scale` 保持 1** | `fromSurface:false` 会让 `captureBeyondViewport` 失效，只给一个视口那么高；`clip.scale` 与 `deviceScaleFactor` 相乘，两个都给 2 得到的是 4 倍图 |
| **那一屏量完排版才报 ready** | main 是轮询 `window.__inquestryExport`。报早了它按一份还没排完版的矩形去裁——安静地产出一张对不上的图，不报错（同 §11 那条过期帧的形状） |
| **渲染侧的失败要报上来，不要让 main 等超时** | 只等超时的话，错误信息只会是"超时"，说不出是取不到快照还是量不到某一块 |
| **分页前后各量一次** | 先按一页装下全部量块高来决定切在哪，再按分完页的真实矩形裁。页眉页脚会把每页加高，拿预算算出来的高度去裁必然错位 |
| **块高要算上它自己那条上外边距** | `getBoundingClientRect().height` 不含外边距，而小节之间那 44px 是实打实占页面的 |
| ⚠️ **边距记在它自己头上，不能按"下一块落点减这一块落点"算** | 后者把那 44px 记在**上一块**名下，而分页之后那一块成了上一页的末尾、边距根本不出现，这 44px 却随新页的第一个小节实打实长了出来——每页都可能比预算高出一个边距。实测超了 34px |
| **每页的固定开销要量，不要列** | 照着样式表把内边距、页脚、页眉一项项加起来估了个 240，实际是 272.83——改一处样式就少算一项，而少算的表现是页面悄悄超上限。量法是"整页高 − 内容高" |
| **装了不止一块的页超上限要当场报错** | 上面那两条错法都不会自己现形（图只是略高一点）。只有单块页可以超——那一块自己就比一页高，而绝不从小节中间切 |
| **先把每页都拍完再动盘上的文件** | 边拍边写的话，第三页才失败会留下前两页——一组看起来正常、其实是半份的报告，与一次成功的导出长得一模一样 |
| **回滚自己失败了也要报出来，并说清备份在哪** | 回滚每一步都是 best-effort，全用空 `catch` 吞掉的话，"失败时整组还原"就是一句不作数的承诺：原图停在 `.inquestry-old` 上、或某几页还是新的，而人只看到最初那个错误，回头找自己那张图才发现不见了。**按结果核不按步骤核**——`rm` 失败之后 `rename` 照样可能盖回去，按步骤记会报一堆已经自愈的"失败"；要回答的只有"那个名字上现在是不是用户原来那张图" |
| **换上去之前把旧的挪开，任一页失败就整组还原** | 光"先写临时文件再 `rename`"不够：换到第三页才失败时，前两页已经被盖掉且旧内容再也找不回来，剩下的仍是半新半旧的一组。⚠️ **还原要认"挪开过哪几个"，不是"换上去了哪几个"**——失败正好落在"挪开了旧的、还没换上新的"中间时，那一页在后一份名单里没有记录，只按它还原的话用户原本那张图就停在 `.inquestry-old` 上不见了（实测栽过） |
| **"能不能装成一页"要按没有页眉的开销问** | 单页不印页眉，而量固定开销时特意让页眉在场。拿含页眉的预算去判，会把一份"差着一行页眉就能装下"的报告拆成两页——它反倒因此真的多出两条页眉，文件名也从人选的那个变成 `-1`/`-2`，违背单页优先 |
| **同名的旧图只报不删** | 单页落 `<target>`、多页落 `<target>-1…N`，同一路径先后导出而页数变了，上一次的产物就留在旁边，看起来正是这次导出的那张。但保存框只问过用户那一个名字——`<stem>-3.png` 是不是他自己的文件、是不是别的案子导的，main 这儿不知道，所以把名字报进回执，删不删由人定 |
| **绝不从小节中间切；超预算的单块自成一页** | 断口落在读者要看的那句话上的概率并不低。翻页条件要按"这一页装了东西没有"判，按预算判会先产出一张空白页，再把那一块放到第二页去 |
| **相邻两页按同一组取整后的边界裁** | 各自四舍五入的话边界差一像素，表现是某一页顶上多出一条上一页的残边 |
| **拍完比对像素尺寸，不符重拍一次再报错** | 这条链路最容易的失效方式不是抛异常，而是安静地给出一张高度不对的图——半截报告看起来只是"内容少了点" |
| **每页都带页脚水印，生成时间由调用方给** | 长图会被转发到看不见上下文的地方，只有第一页带编号的话，被转走的那一页就是一段无从溯源的截图。时间自己读时钟则产物不可复现（同 §7.1） |
| **单页保持人选的文件名，分页才加 `-N`** | 单页是绝大多数（单页优先）。⚠️ 分了页之后盘上**没有** `<target>`，第一张是 `<target>-1`——无人值守探针照着原路径去读会报 ENOENT，它该走生产那个命名函数 |
| **超长不是靠上限兜住的** | 实测拍到 24000px 仍然画得全（底部标记还在），所以 6000px 这条分页线是为读的人设的，不是绕开纹理上限 |

回执与失败：同 §7.1 那一套 `ExportResult`（取消与写盘失败分开、`invoke` 自己 reject 那条路也要接）。**长图多一条**：整条链路里出错的地方多了几处（那一屏没排出来 / 尺寸不符 / 写盘失败），它们都要落到同一条可见回执上。

> ⚠️ 必须等 `document.fonts.ready` 与两帧 `requestAnimationFrame` 再量：字体没就绪时量到的是回退字体的高度，分页会按一份错的排版切。

## 8. 案子的一生

前面几节只描述了"案子正在进行"这一个瞬间。日常用起来还要回答四件事。

### 8.1 立案

顺序是**先选项目起点，再写问题**：

- **项目起点**（本地路径）—— agent 在这个目录下运行，继承该项目的 skill 与 MCP 配置（[overview](overview.md) §2 "白送的能力"），会话记录也落在 `~/.claude/projects/<dir>` 的对应目录。给最近用过的路径做快捷入口
- **问题** —— 自由文本
- **事故基准日** —— 见下。时区不收，取本机的
- **已知线索**（可选）—— 涉及服务 / traceId / 用户 ID / 报错码。填了能省掉 agent 前几轮试探，不填也能跑
- **Agent / 模型 / 思考强度** —— 见下
- **权限模式初值** —— 分层放行（默认）/ 全程接管，随时可切

**Agent 三项落在 `sessions` 而不是 `cases` 上。** 一个案子跨多个会话（§4.1），中途换模型是常态——先用便宜的扫一遍，再换强的推。放 case 层会让"这一步是哪个模型跑的"永远答不上来，而报告里需要标出它。

| 项 | 说明 |
| --- | --- |
| backend | Claude（当前唯一实现）/ Codex（未接入，占位显示为禁用而不是隐藏） |
| model | 按 backend 列举，切 backend 时整个列表换掉 |
| effort | 思考强度。**不是所有 backend 都有**——走 D19 的能力协商，backend 不支持就整项隐藏，而不是给个假开关 |

> **模型列表是问出来的。** `query.supportedModels()` 返回每个模型的 `supportsEffort` 与可用档位——实测 Haiku 一档都没有，Opus / Sonnet / Fable 是 low→max 五档。写死一张表就一定会在这里给出拧了不生效的假开关。
>
> 代价是探测要 spawn 一次 CLI，所以：带超时、缓存进 `ui_settings`（24h）、问不到就退回内置表**并在面板上明说这是兜底**。backend 自己报的「默认」那一档直接当作"不指定模型"，不把 `default` 当模型名传下去。

> **基准日是硬需求，不是"可选线索"。**
> 日志时间串大多既没有日期也没有时区（`12:03:01.220`）。没有基准日，`occurred_at_ms` 落不成绝对时刻，事故时间线就排不出来（[data-model](data-model.md) §2）。它由立案面板收集并落 `cases`，同时**写进首轮提问的正文**——harness 与 agent 两边补齐时间串的基准必须是同一个，否则一条证据在库里和在报告里会落到两个时刻。
>
> 填错了不会报错，只会让事故时间线悄悄排乱。所以**提交前就校验**（日历上不存在的日子直接拦下），并且**常驻顶栏**，不是填完就消失。

**时区不给用户填，取立案机器的本机偏移并落库定死。** 让人手填一个 `±HH:MM` 是把一个几乎总是同一个值的东西做成了一个能填错的空——填错的后果是所有无时区证据整体偏移几小时，而且没有任何报错。取本机值同时也去掉了一整类校验（`+14:59` 这种格式合法但不存在的偏移）。

> ⚠️ 取的是**事故那一天**的偏移，不是此刻的。有夏令时的地区冬夏差一小时（实测 `America/New_York` 冬 `-05:00` 夏 `-04:00`、`Europe/Berlin` 冬 `+01:00` 夏 `+02:00`），冬天立一个夏天的案子就会把所有只有时分秒的证据整体挪一小时。面板上显示的偏移与落库的偏移必须来自同一个函数、同一个日期，各算各的迟早对不上。

**项目起点要在立案时就验**（存在、是目录、可读可进、绝对路径）。不验的话坏路径照样立案成功，要等点「开始排查」才由 SDK 抛错、会话直接 `crashed`，而那时它已经进了最近目录列表。校验失败要指明是哪个字段，面板才有地方显示。

> 代价要写明：**本工具因此假设「日志时区 = 立案机器时区」。** 排查异地部署的系统时这条会错，错法是整条事故时间线整体平移。真遇到了要加的是「按案子纠偏时区」的入口——纠偏必须留痕（走事件），因为它会改变一批已落库证据的时刻。

立案创建的是 **Case 不是 Session**——一次事故跨多会话（§4.1）。重开旧案时以库里那份立案单为准，本次不覆盖：基准日一旦变过，已落库的 `occurred_at_ms` 就对不上了。

**Session 要到真的跑第一轮时才开。** 立案与开会话时机不同，合在一起会让"打开 app 看一眼上次那个案子"每次都留下一条没有任何 turn 的空会话，越攒越多，还会污染"这一步是哪个模型跑的"。因此顶栏显示的 agent 三项取自 runner 手里的选择，不是 `sessions` 表——会话还没建时也得显示待会儿用哪个模型。

> 代价是**立案时选的 agent 一时无处可落**（`sessions` 还不存在），而"立完案先不跑、明天再说"是常态。所以它同时写进 `case_ui_state`，重开时按「上次跑用的 → 立案时选的 → 默认」取。少了这一步，重启后会静默换回默认模型，人选的那套连同顶栏显示一起消失。

**项目起点决定挂哪套工具**，不只是记录一个路径：填了就是真项目（`cwd` 指过去、加载该项目的磁盘 settings、直接给 Read/Grep/Glob 三件套），不填就是演示事故（隔离模式 + 内置玩具数据源）。把玩具数据源留在真项目里比没有它更糟——agent 会拿假订单日志当证据。

> `settingSources` 必须含 `project`，否则读不到该项目的 `CLAUDE.md`——「继承该项目的 skill 与 MCP」就只是句话，agent 会在缺项目约束的上下文里排查。演示模式反过来用隔离模式（`[]`），因为它要的是可复现。

> 🔴 **"放开的是上下文不是权限"这句话是错的，实测推翻。** 磁盘 settings 里的 `hooks` 是一串 shell 命令，**加载即执行**：在一个只有 `.claude/settings.json` 的空仓库上立案，`SessionStart` 与 `PreToolUse` 两个 hook 的命令都在宿主机上跑成了，没有任何提示，也不经过 `canUseTool` / `PreToolUse` / `disallowedTools`——`SessionStart` 甚至发生在第一次工具调用之前。项目 `.mcp.json` 里的 MCP server 同理，是直接拉起的进程。
>
> 所以三分法**只管得住 agent 自己发出的工具调用**，管不住仓库自带的配置。真正的信任边界是「你在立案面板里选的那个目录」，与在那个目录里直接跑 `claude` 等价。SDK 没有提供关掉磁盘 hooks 的开关（`managedSettings` 是限制性策略层，没有这一项），只有不加载那些 setting source 一条路；MCP 那一半可以用 `strictMcpConfig` 单独关掉。
>
> 这条对本工具尤其扎眼：**它被指向的仓库，正是"有什么东西不对"的那个**。已决定按"自己的仓库自己负责"接受该风险（单人自用，指的都是自己的仓库），备选缓解见 §12。

#### 工具面分三档，与§4 的三级同源

| 档 | 有哪些 | 怎么过 |
| --- | --- | --- |
| 直接放行 | 三个结构工具 · `ask_operator` · 记事本与工具检索 · 真项目下的 Read/Grep/Glob（演示模式换成玩具数据源） | 不记闸门，节点上不标 |
| 过闸门 | **其余一切**，数据源类 MCP、子 agent、联网都在内 | ②档待办，三分钟没人管就按预设放行 |
| 一律不给 | Bash / Write / Edit / NotebookEdit 这类跑命令与写盘的 | 同时进 `disallowedTools`，模型连看都看不到 |

第三档不走 `canUseTool` 一条路守：真项目会加载该项目自己的 settings，里面若有 allow 规则，闸门根本轮不到发言。

> ⚠️ 第三档挡的是 **agent 要不要跑命令**，不是「这台机器上不会有命令被跑」——仓库自带的 hook 照样会跑 shell，见下面那条红字。

> ⚠️ **实跑打出来的**：`canUseTool` 只在 backend 自己决定"要问"的时候才被调用。只读工具按默认模式直接放行，白名单压根没参与——第一次跑出来 `Read` 记着 `gate_decision='auto'` 就是这么来的。**每次调用都到的是 PreToolUse**，所以想拦谁必须在那儿回 `permissionDecision: 'ask'`，把它推到 `canUseTool` 上去。反过来，放行那一档要回空而不是回 `allow`：明写 allow 会盖掉项目自己的 deny 规则（比如不许读 `.env`），这里要的是别多管，不是抢权。

### 8.2 中途插话

四种方式，对应 §3 的三档控制语义：

| 方式 | 语义 | 落到哪 |
| --- | --- | --- |
| 底部输入带 | 异步入队，**不打断**（§3.3） | 轨道插入一个「补充」标记节点，可撤回 |
| 选中某个节点再说 | 同上，但消息带 step 引用 | 补充挂在那个节点下，比全局输入框精确得多 |
| 拒绝并留话 | `deny + message`，turn 不中断（D6） | 该调用记为"被拒"，留话进节点 |
| 改写参数后放行 | `allow + updatedInput` | 记 `input_rewritten`，改后的语句一起回传 |

后两条各有一个只在装起来之后才看得见的收尾：

- **被拒的调用不会有 `PostToolUse`**，不在拒绝那一刻补一次收尾，它就永远挂在 `pending` 上。留话原样落 blob——它就是 agent 收到的那份工具结果，节点上要看得见拒绝理由
- **判决落在哪条事件上取决于到达顺序**：`PreToolUse` 先到就补一条 `toolcall.gated`，闸门先落定就由 `toolcall.started` 直接带走。所以别去数 `gated` 的条数，要验就验重放后判决是否逐字一致（`npm run spike:gate`）

> ⚠️ **撤回有粒度坑**（§3.3）：多条排队消息合并成一个 turn 后，撤回非代表 uuid 是空操作，撤回批次代表 uuid 会丢整批，两种都报"未取消"。UI 要么不给批内单条撤回，要么明说"会连同这批一起撤回"。

### 8.3 并发多个案子

已实现，形状如下（`src/main/case-registry.ts` + `CaseBar`）。

- **案件切换栏**：顶栏下面一排 chip，进行中的排在前面（`ORDER BY (status='open') DESC, updated_at DESC`），各带一个徽标：等你 N（暖色）> 跑动中 > 已停 / 未打开 / 已结案。切换不中断任何一个——main 持有全部运行时，renderer 只切投影
- **待办计数跨 case 全局汇总**。并发场景里最容易漏掉的一条：你在 A 案上工作时，B 案卡在 `ask_operator` 上等你；只在当前 case 显示的话那条支线会静静挂死。落法是每个案子的 chip 自带「等你 N」，顶栏另有一颗描边的「别的案子 N」，点它直接跳过去
  - 汇总走 `todoCount` 这个便宜读数，**不走 `buildSnapshot`**：快照每 60ms 推一次，全量投影乘上案子数扛不住
- **活跃会话限流**（沿用 duetlens 的活跃会话 LRU）：`MAX_LIVE_CASES = 3`，限的是真的 spawn 了进程的那些（`sessionStatus === 'live'`），不是载入的案子数。超上限降级最久未交互的
  - ⚠️ **三种不能选：当前这个、正在跑的、挂着待办的。** 最后一条最容易漏——降级会把等着人回答的 pending 就地作废，等于替人做了「这条不查了」的决定，而 ①档故意没有超时兜底正是因为自动填个假结果比让人等着更糟。挑不出人选就让它超一个（软上限），拒绝新建或杀掉等人的支线都更糟
  - 降级要把运行时**从表里删干净**，不能留着一个已 `ended` 的：留着的话下次点开会往那个已收尾的 session 里接着写
- **重开旧案 = 新起一个 session**，`ordinal` 因此每个会话都从 1 重来，轨道上用「第 N 次会话」分隔线标出断点（只有一次会话时不标，那条线什么都没说明）
> ⚠️ **切换是同步生效的，界面慢一拍。** main 一收到 `case:switch` 当时就换了当前案子，
> renderer 要等下一次快照（最多 60ms）才换屏，这中间旧界面照样发得出调用。三条都得做到：
>
> - **凡是作用在当前案子上的 IPC 都要带 renderer 那一屏的 caseId**（`send` / `start` / `restart` /
>   `interrupt` / `answerOperator` / `decideGate`），main 用 `currentIf(caseId)` 核对，对不上就不执行。
>   ⚠️ **「按 id 查表，查不到就自然安全」是错的**：查不到 = **静默什么都不做**，而两档的后果都不是无事发生——
>   ①档是人贴进去的结果凭空消失、回填挂到超时；②档更重，人按了「拒绝」却没落地，三分钟后按预设**自动放行**
> - **两个处置手势要回执成功与否**，没落地要说出来（那时卡片多半已经不在屏幕上，提示得挂在应用级）
> - **人敲进去的东西一律提到 App 级**，按「caseId + 条目 id」存。卡片跟着快照渲染，一切案子就卸载，
>   局部 state 随之蒸发。清理**不能只靠处置回执**：闸门自动放行、回填超时、停止/重开散掉待办、runner 被回收
>   都会让卡片消失且没有回执，要拿当前快照的 id 对账（`renderer/drafts.ts`），且**只对账快照里那个案子**

- **历史**：entry 屏的 Case 列表 + FTS5 跨 case 检索。找旧案子的心智是"上次那个从库延迟的"，所以检索要能按根因形态 / 涉及服务 / 时间筛。中文查询串不足 3 字时回退 `LIKE`（[data-model](data-model.md) §5）。**尚未实现**，切换栏目前只列最近 20 个

### 8.4 三种收尾，不是一个按钮

与 §3「三档粒度不要混成一个 Stop 键」同源。

| 动作 | 对 agent | Case 状态 | 之后 |
| --- | --- | --- | --- |
| **停止** | 中断当前 turn，连排队消息一起清（D7） | `open` | 随时新开 session 接着查 |
| **结案** | 先走完影响面与遗留疑点两个强制 step（§6.2） | `closed` | 冻结，只能导出 |
| **归档** | 同"停止"，外加标记放弃 | `aborted` | 仍可导出**残报告** |

**提前终止不销毁任何证据**——与"结论可以被推翻，事实不会"（[data-model](data-model.md) §3）同一条原则。终止只做两件事：

1. 挂起中的 pending 一律改判 `abandoned`，否则库里会攒下永远 resolve 不了的僵尸节点（[data-model](data-model.md) §4）
2. 给 Case 打上状态

**残报告的形态强制为 `open`（未决型）**：主体是排除矩阵与遗留疑点，顶部明写"调查在第 N 步被人为终止"，**没有根因栏**。没查出来就是没查出来，不编——这比一份看起来完整实则半截的报告有用。

### 8.4.1 落地时才看清的约束

由 `npm run spike:close` 兜底。**改这一带之前先跑它。**

**状态变更走 `case.status_changed` 事件，不直接 `UPDATE cases`。** 重放时 `case.opened` 会把 status 写回 `open`，直接改的库值一重建投影就没了，而且没有任何报错——症状要到换 schema 那天才出现。

**「散掉挂起的待办」是两件事，不是一件。** 逐条 resolve 掉那个 Promise 只做了一半；那次调用还记在 `pending` 上，不收的话库里会攒下一批永远等不到结果的调用。闸门那侧一直是两件都做，回填这侧原先只做了第一件——因为**两边的键根本没连上**：账上是 backend 的 `toolUseID`，回填卡上是自己发的 `ask_*`。

连线按**语句**认领，不按先后（子 agent 能同时问出好几条，按先后认会把甲的放弃记到乙头上），而且**认不到就认不到，不拿队首兜底**——猜一个的代价正是把别人那次调用记成放弃、真正该收的那条继续挂着。散场时要扫的因此有两批：已经进了 `pending` 的，和**记了账还没被认领的**（PreToolUse 记完、工具正文还没跑到那一小段里撞上停止），后者不收就只有下次启动清扫才纠正得回来。

**散场要收的不止「卡在人这儿」的那两种。** 结案/归档会 `close()` 掉查询，而 SDK 保证 `close()` 之后不再有任何消息——一次已经自动放行、还在跑的 Read 或日志查询，库里只有 `started`，`PostToolUse` 永远不会来。忙着的时候归档是允许的动作，不收的话冻结后的报告里那条永远显示「进行中」，一直挂到下次启动清扫，而那时案子早就冻上甚至导出了。所以收尾最后要按库里的 `pending` 扫一遍当前会话，**不认识它们是什么也照收**。中断走的是另一条路：它不关查询，在跑的调用由 `PostToolUseFailure` 带 `is_interrupt` 自己收尾。

**但散场只收「还没着落的」，不改写已经有结论的。** 那批没被认领的不保证还是 `pending`：一次 `ask_operator` 在 PreToolUse 之后因参数校验失败走了 `PostToolUseFailure`，账上已经是 `failed`，而条目还留在队列里（只有被认领时才会清）。无条件改判就把它盖成了 `abandoned`，丢掉的正是那三种"没跑成"的区别。这道保护放在 `abandonCall()` 里而不是各个调用点——闸门散场那条路一样够得到已经被规则判过 `denied` 的调用。

**散场之后 PostToolUse 还会来一趟。** 散场靠的正是"给工具那侧一个结果"，那次调用随后照样走完 PostToolUse——不挡这一下，刚记下的 `abandoned` 会被改写成 `done`。与 §8.2 被拒那条同源。

**结案校验与报告章节必须共用同一条「哪一步算数」的规则**（`effectiveStep`：排除已被推翻的，取最新那条）。各算各的会漏两种，两种都让报告的影响面栏空着或印错：

- 只问"历史上有没有一条收好的 impact"：agent 收好一条之后又新开一条打算重做、还没 `close_step`，校验照样放行——而报告取的是**最新**那条，于是那一栏是空的
- 不排除 `superseded`：结论已被明确推翻。被同类新 step 顶掉不影响（新的自己接上了），漏的是被**别的 kind** 推翻那种——章节看着齐全，报告却把一份作废的影响面照印不误

缺步时不报错就完，而是把这两步派给 agent 去补（会话已经不在就如实说"派不出去"）；就此收手走归档。

**「问还差什么」与「执行结案」必须是两个入口。** 合成一个的话，界面只能靠快照决定这一下是问还是执行——而快照是 60ms 合流推的：agent 刚补完最后一步、这一屏还没收到时，按钮上写着「差 1 步」，点下去却落进执行路径，把案子不可逆地冻上且完全没经过确认。拆开之后，问询那条路**永远不改状态**（缺了就派活给 agent），执行那条路**只回绝、不派活**（缺步说明界面那份快照过期了，或者确认条挂着时强制 step 被推翻了，这时该做的是不动手）。

**确认的回执要落地，没落地就别把确认条收掉。** 确认条挂在屏幕上的这段时间里，强制 step 可能被推翻、案子可能被切走，两种情况 main 都会回绝。真 app 里实测过旧写法：确认条收起、没有任何提示、案子其实还开着——人会以为已经结案了。

**「点下去就没有回头路」的手势必须自己带上 caseId。** 确认条只记动作的话，在 A 案弹出后切到 B 案，那条 state 还在，而按钮那一下取的是**当时**的当前案子——真 app 里实测过：切过去再点「确认归档」，被归档的是 B，A 还开着，而确认文案讲的是 A 的事。三道一起上：切换时清掉、渲染时核对 `caseId`、执行时用**弹出时**那个 id（main 侧的 `currentIf` 于是会整个不执行，而不是落到新案子头上）。同一页的输入草稿、卡片草稿早就是按案子分开存的，唯独这条当时漏了。

**冻结是真的冻**：`closed` / `aborted` 的案子 `start()` 不再新起会话、`send()` 回 false、输入框禁用。不冻的话新步骤会追加到一个已下结论的案子上，报告与它记录的过程就此对不上。

**加了终态就要回头看一遍现有的动作有没有变成死控件。** `lastError` 那条横幅带着「重开一轮会话」，冻结之后它点了毫无反应（`restart()` 最终走 `start()`，而后者对已收尾的案子直接返回）。留下错误本身、去掉按钮——那句错误多半正是当初放弃的原因。

**收尾要顺手把 `busy` 清掉。** `consume()` 的 finally 认的是「`this.q` 还是自己那次查询」，而 `close()` 上一行刚把它置空，那一轮醒来时直接 return——收尾这条路上没有别人会来清。留着 `busy=true` 不只是切换栏一直显示「跑动中」：`trimIdle()` 跳过忙着的运行时，于是每收尾一个就永久占住一格，`MAX_LOADED_CASES` 形同虚设。

**启动清扫赶在任何 runner 之前**（`main/index.ts` 里紧跟 `openDatabase`）：那一刻库里所有 `pending` 的调用与 `live` 的会话都必然是上个进程留下的。建完 runner 再扫会把这一轮自己的活计一起判成放弃。

### 8.4.2 结案那一下要选报告形态

结案确认条上多一行五选一：时序型 / 状态型 / 因果链型 / 分布型 / 未决型（D25，取值与主体块见 [overview](overview.md) §6.1.1）。它是**这一步唯一需要人做的判断**，也是 `cases.verdict_shape` 唯一的写入方。

**预选值一路备好，人不动手也能一路按到底**：agent 在 `close_step` 里声明过就预选它的，没声明就预选 harness 推断的，两者在选择条上分得出来（「agent 判定」/「没人判定过，按现有数据推的」/ 人动过手之后是「你选的」）。两层结构与推断规则在 [data-model](data-model.md)。

不要改回去的：

- **摆在确认条里，不单开一屏。** 形态决定报告装哪几块，而"确认结案"正是唯一看得见后果的那一下。拆开的话，人会在还不知道要选什么的时候先被问一次
- **它跟着确认条那份 state 走，不每帧从快照取。** 快照 60ms 一轮，而人正在这条上挑——取快照的话手上选的会被下一轮冲掉。这是 §8.4.1 最后那条约束（不可逆手势要自带上下文）的第二个实例，同一条理由
- **冻的那一份要由 `requestClosing()` 带回来，不从界面自己的快照取。** 界面那份是点击那一帧的闭包值，隔着这次 await：main 按最新状态放行了弹窗，界面却冻一个过期的推断值，把 agent 刚落定的声明盖掉。形态与缺口必须出自**同一次库状态**——与"不拿快照上的 `closingGaps` 决定该弹确认还是派活"是同一条理由，只是这次轮到了形态
- **界面给什么就用什么，认不出来才退回建议值。** 落一个 NULL 进去的后果是报告没有装法，而那要到结案之后才发现
- **形态与它的出处要一起冻。** 只冻值不冻来源的话两者会错配：确认条挂着的这段时间里 agent 补了一条声明，屏幕上显示的还是弹出时那个推断值，标签却变成了「agent 判定」——而 agent 声明的其实是另一种形态，人照着一个错的出处按下了不可逆的那一下
- **「人动过手没有」要显式记，不能拿"当前值 ≠ 建议值"推。** 挑过别的又切回建议值会重新显示成 agent 判定；建议值自己变了的话，人一下没碰过也会被标成"你选的"。这一下不可逆，来源标错等于替人认了一个判断
- **状态型没有应然/实然时压暗提示，但不禁用。** 那一对是它的报告主体，缺了这一块是空的，所以要在人按下去**之前**说。不禁用是因为人可能确实知道故障是这一类，而 agent 没填那一对——根因那一步已经收口了，它补不回来，禁掉等于把人堵死在一个它自己造成的缺口上
- **「填不填得出来」按根因认，不是一律信实时也不是一律信冻住的。** 一律信冻住的，agent 随后补上那一对之后警告再也不消失；一律信实时的，**根因换了人**时两者指着不同的步——预选的是新根因声明的 `state`，却按旧根因判定成"填得出来"，一句提醒都没有，人当场确认就冻出一份空主体报告。所以建议里带上 `rootStepId`：还是同一步就信实时的，换了人就用冻住那份（判断在 `renderer/drafts.ts`，由 `spike:cases` 兜底）
- **推断值宁可少装一块，也不装一块空的。** 没有已证实的根因才推 `open`——有结论却推 `open` 等于把它从报告里抹掉；有结论而带时间的证据不足两条时也不推 `sequence`，那一块会是一行孤零零的记录

归档不给选：残报告一律未决型，**盖掉 agent 声明过的任何形态**。

agent 那侧的对应负担只是 `close_step` 上多一个可选枚举（外加状态型的 `expected` / `actual` 一对）。填了不生效的情形一律当场回警告——不当场说的话，agent 以为自己已经交代过了，而报告要到结案那天才发现那一栏是空的。**清单以 [tools](tools.md) §6.1 那张表为准**，不在这儿抄一份：抄了就会像上一次那样，实现补到五种而这里还写着三种。

## 9. 全量快照推送，不做增量 diff

main 每次领域事件后重算整个 `Snapshot` 推给 renderer（60ms 合流）。

理由不是"数据小所以偷懒"，而是**增量 diff 的错法是静默的**：漏推一类节点，UI 上就是那类东西不存在，没有任何报错——duetlens 上「Discussion 栏整个为空却无人报错」正是这个形态。等数据量真的顶不住再换增量，那时至少有个能对照的正确实现。

## 10. 装起来才暴露的问题

前面四个 spike 全在 tsx 里跑，这些一个都不会出现：

| 问题 | 现象 | 结论 |
| --- | --- | --- |
| **ESM preload 需要 `sandbox: false`** | 窗口全黑、无任何报错 | Electron 只在关掉 sandbox 时加载 ESM preload，否则**静默失败**，`window.inquestry` 未定义、React 首个 effect 抛错整树卸载 |
| **schema 不幂等** | 第二次启动崩在 `table events already exists` | 全部 `CREATE ... IF NOT EXISTS` + `user_version`。投影可从 events 重放重建，所以迁移不必写数据搬运 |
| **case 每次启动都重开** | `UNIQUE constraint failed: cases.id` | 一次事故跨多会话（§4.1）：case 只开一次，每次启动是它下面的**新 session**。这条崩溃反而印证了 Case > Session 分层是对的 |
| **schema / 提示词用 `readFileSync` 读源码目录** | 开发期正常，打包必炸 | schema 改成 TS 常量；提示词由构建期 `?raw` 内联。两者都是启动必需品，这类失败只会在装机后才暴露 |
| **`canUseTool` 不是每次调用都到** | 白名单里没有 `Read`，它照样跑完，还记着 `gate_decision='auto'` | 只读工具按默认模式直接放行，backend 觉得不用问就不会问。**闸门的入口是 PreToolUse**，回 `permissionDecision: 'ask'` 才推得到 `canUseTool`（§8.1） |
| **一个 inbox 只能配一个 query** | 点「重开一轮会话」后库里有了新 session、界面显示进行中，agent 却什么都没收到，全程不报错 | `createInbox` 是 async generator，**只能有一个消费者**。`close()` 里必须换掉 `this.inbox`，否则开场白被正在收尾的旧查询取走，或旧迭代器一关、新查询直接看到 done。⚠️ 验这条**必须真去消费那个 generator**，只比较 inbox 引用是验不出来的 |
| **一轮失败 ≠ 会话结束** | 凭据过期后界面显示「会话中」，主区空白，输入框还能发但发不出去 | 消息流**不会自己结束**（实测 25s 后仍开着），`for await` 不返回，状态永远停在 `live`。只能靠 result 消息的 `is_error` 判断，⚠️ **`subtype` 那时仍是 `"success"`**，信它必错。判到之后要给一个显式的「重开一轮会话」——否则唯一的出路是重启 app |

renderer 的报错默认只留在它自己的 devtools 里——`console-message` / `did-fail-load` / `preload-error` 三个事件必须转发到 main 的 stdout，否则每次都只能盯着黑屏猜。

## 11. 开发期自检

**两条现成命令，别自己拼**：跑全套自检 `npm run spike:all`，跑 app（含无人值守探针）`npm run app`。两者各自把 ABI 切好再跑——`better-sqlite3` 装完 Electron 之后只对一个 ABI 有效，而**忘了切的表现是 app 停在启动失败屏上干等到超时**（`NODE_MODULE_VERSION` 对不上）。这一条同一天栽了两次，所以绑进脚本，不靠记。

harness 侧的记账、状态与投影由 spike 兜底，改哪一带先跑哪一条：`spike:db`（数据模型）· `spike:tools`（工具契约）· `spike:wire`（主干接线）· `spike:lane`（子 agent 泳道）· `spike:gate`（闸门与收尾）· `spike:cases`（并发多案子）· `spike:close`（三种收尾）· `spike:track`（轨道布局）· `spike:branch`（子 agent 泳道接进轨道与收口）· `spike:report`（报告章节组装）· `spike:markdown`（Markdown 导出）· `spike:image`（长图分页）。**`tools` / `wire` / `lane` 要起真会话、靠订阅凭据，不在 `spike:all` 里；其余都进 `spike:all`**（`report` / `markdown` / `image` 是纯函数，连库都不碰）。单跑某一条时若刚跑过 app，先 `npm run rebuild:node`（`spike:all` 自带）。

renderer 的状态没有 node 侧的回归网。验它用**临时探针**：在 main 里加一段 env 开关的 `executeJavaScript` 脚本，驱动真 app（点按钮 → 读回 DOM），验完把探针删干净。能提成纯函数的（`renderer/drafts.ts`）就提出来进 spike。

无人值守跑一轮并截图，用于没人盯着屏幕时验证 UI：

```bash
INQUESTRY_AUTOSTART="<问题>" INQUESTRY_AUTO_OPERATOR=1 \
INQUESTRY_SHOT="a.png@25000,b.png@75000,c.png@150000" \
INQUESTRY_SHOT_REPORT=report-screen.png INQUESTRY_SHOT_QUIT=1 \
INQUESTRY_EXPORT_MD=report.md INQUESTRY_EXPORT_IMG=report-long.png \
npm run app
```

`INQUESTRY_EXPORT_MD=<路径>` 会**从报告屏的按钮按下去**导一份 Markdown（renderer → preload → main → 写盘 → 读回回执，再核文件非空），失败即抛。有这个 env 时界面那一下也不弹保存框，直接落到指定路径——不然无人值守会卡在保存框上。

`INQUESTRY_EXPORT_IMG=<路径>` 同理导一张长图，另外核**盘上那张图的像素尺寸**：宽必须正好是 @2x 的 2480px（`capturePage()` 那条"倍率跟着显示器走"只有在真 app 里才验得到）。**高度这一侧不设阈值**——一份短报告本来就该出一张矮图，"截了半张"由 `exportImage()` 拿量出来的矩形当场核。⚠️ 分了页时盘上没有 `<路径>`，第一张是 `<路径>-1.png`。**两个候选里按"这次导出之后才写的"挑，不能按"哪个文件在"挑**：上一轮导过单页、这一轮分了页时，旧的 `<路径>` 按设计留在原地，"谁在就挑谁"会挑中它——实测的表现是探针**核了上一轮那张图还报成功**（换个先后就变成把一次成功的导出报成失败），而本轮真正的第一页压根没被核过。

> 🔴 **两种导出接连跑时，"读回执"这一步会骗人**（实测）：长图那一段会立刻读到 Markdown 那条还挂在屏上的回执，`已导出到` 照样匹配；它接着去核的那张图**可能是上一轮留下的**——文件在、尺寸也对，两条断言全过，而这一次导出根本没跑。所以按下之前先关掉旧回执，并记一个时刻核图片的 mtime。**凡是"读界面上那条状态"的探针都有这个形状。**

**它单独设也能跑**，不必陪一个截图变量（这四个开关任一存在就挂这段自检）。库里只剩冻结的案子时启动会停在立案面板（只恢复 `open` 的那种），探针会先从切换栏点进那个案子——和人会做的动作一样。⚠️ 点之前**要等界面到位**：`did-finish-load` 比第一份快照早，那一刻连顶栏都还没有，不等的话报的是"没有导出按钮"，而按钮只是还没画出来。**`INQUESTRY_SHOT_REPORT` 单独设时是同一个坑**——不带 `INQUESTRY_SHOT` 时它是 `did-finish-load` 后第一件事，比首份快照还早，报告屏与 `.toreport` 谁都还没渲染，同样要先轮询等到位再摸。

失败**无条件**以非零码退出，不看 `INQUESTRY_SHOT_QUIT`——那个开关只管"成功之后要不要自动退出"。合在一起判的话，单独设 `INQUESTRY_EXPORT_MD` 跑失败会让进程一直挂着，调用方（CI、脚本）拿不到能判定失败的退出码。

`INQUESTRY_AUTO_OPERATOR` 用数据源给的建议答案代替人回填，**同时把②档闸门一律放行**——不放的话跑到第一个闸门就停在那儿，而它三分钟后才自动放行，截图早拍完了。要拍闸门本身反过来别开这个开关。

> **它同时暴露了一个真实风险**：建议答案对不上问题时（拿订单行去答"索引是什么"），agent 当场识破并拒绝把结论算作已验证——与 tools.md §5 观测到的行为一致。

> ⚠️ 窗口未获焦点时 `capturePage()` 会返回**过期帧**，截图看起来"停在几十秒前"。判断进度以库里的数据为准，不要以截图的时间戳为准。同一个坑在长图导出里必须显式规避（§7.2）。
>
> **实测：点进报告屏后 400ms 拍到的，与点击前那一张字节完全相同。** 固定等一会儿再拍是不够的——探针改成留一帧点击前的，等到画面真的变了才算拍到，等不到就抛。已经在报告屏上（收尾会自动翻过去）则不点也不报错。
>
> ⚠️ `did-finish-load` 回调里抛出去的异常**没人接**：表现是无人值守跑干等到超时、一行日志都没有。这一段包了 try/catch，失败打日志并以非零码退出。

## 12. 当前欠缺

- 🔴 **仓库自带的配置是被信任的**：真项目模式加载 `project` / `local` settings，其中的 `hooks` 加载即执行 shell、`.mcp.json` 直接拉起进程，三档工具面完全管不着（§8.1 有实测）。**已决定维持现状**：信任边界就是「你在立案面板里选的那个目录」，与在那儿直接跑 `claude` 等价——本工具是单人自用，指向的都是自己的仓库。要改的话，代价从小到大是：① 加 `strictMcpConfig` 堵住 MCP 那一半（hooks 照旧）；② 立案时加「信任这个仓库的配置」开关，默认隔离；③ 真项目也一律隔离，代价是 `CLAUDE.md` 与项目 skill 全丢，而那正是当初要它的理由
- **闸门只有三分钟一档**：`GATE_TIMEOUT_MS` 写死，既不能按工具分档，也不能"这次先别问了"。真跑几个案子才知道该不该加"本会话一直放行这个工具"
- **闸门判决不进事故时间线**：被拒的调用留在轨道上，但"人在几点拦了什么"目前只有 `tool_calls.started_at`，报告里讲不出这条线
- **立案单立完不可改**：基准日填错只能重新立案。顶栏常驻显示是为了让错误早点被看见，但改不了
- **形态定了就改不了**：`verdict_shape` 只有结案那一下这一个写入方（§8.4.2），选错了没有回头路——与"收尾没有回头路"同源，但这一条的代价小得多（它只影响报告装哪几块，不影响任何事实），真选错过再说
- **归档不问理由**：残报告一律未决型是刻意的，"在第 N 步被人为终止"这句已经在报告顶上了（N 取案子里的步数——冻结之后不会再有新步骤），但没有原因，因为 `cases` 没有列可落
- **收尾没有回头路**：结案 / 归档之后案子就冻住了，冻错了只能另立案件。`case.status_changed` 的载荷留了 `open` 这一档（改回去是表示得出来的），但没有入口——真按错过再说，先不加一个更容易按错的按钮
- **归档不收「为什么放弃」**：`cases` 没有列可落，宁可不收也不留个填不进库的字段。残报告顶部那句"在第 N 步被人为终止"因此只有第 N 步，没有原因
- **旧案子只列不搜**：切换栏取最近 20 个（当前 / 跑着的 / 挂着待办的额外钉住，不被截掉），FTS5 跨 case 检索还没接上去（§8.3）
- **一轮失败之后会话不会自己收尾**：只给了「重开一轮会话」这个出口，没有区分「这次失败可以重试」与「这个会话已经废了」。凭据过期属于后者，但眼下两者走同一条路——重开会丢掉整轮上下文（§10）
- **时区只能是本机的**（§8.1）：排查异地系统的日志时整条事故时间线会平移，目前没有纠偏入口
- **开发期换 schema 会重建库**：旧库改名留着，但案子要重新造（[data-model](data-model.md) §2）
- **支线内部的推理仍然看不见**：收口只取它最后那一句话（`SubagentStop` 的 `last_assistant_message`）。
  完整 transcript 落在 `~/.claude` 下，`getSubagentMessages` 读得到，但报告要的是判断与索引不是原文，
  而它是随时会被清掉的外部文件——真要展开支线的推理过程，得先想清楚存在哪儿
- **支线查到的证据进不了证据索引**：`close_step` 的 `callRef` 只在**它自己那一步**里解析，
  而支线那一步由 harness 收口、没有 `evidence`。所以支线的原始输出留着（点得开），
  却没有任何一条带 claim 的证据指向它。要改的话得让主线够得到那一步的 id，
  而"支线不记账"这条纪律正是为了不让它们互相收步——先攒几份真报告再说
- **一次工具调用都没打的支线不留痕**：兜底步只在第一次调用时才开，所以那种支线只在对话带上有一句话。
  为它造一个空步等于在轨道上多一个从没查过任何东西的节点，宁可不造
- **长图里的日志片段还无处可裁**：§7.2 说的"只保留命中行 ±3 行并高亮"目前无从谈起——报告屏压根还没有展示日志原文的块（证据只以判定与出处的形式出现）。等报告里真的印原文时，这一条要跟着一起做，否则长图会把整段日志铺进去
- **打印那一套没做**：§7.2 里 `@media print` 是唯一的例外（深色页打印要么费墨要么被浏览器反色），眼下报告屏直接打印仍是深底
- **多页长图没有在真数据上出现过**：这一带的分页是把上限临时调小逼出来验的（三页，页眉与页脚都对）。真报告要多长才会分页，得攒够几份真案子才知道——`单页优先`说的正是它本不该常见
- **报告的 H1 是问题的前 40 字**：`cases` 没有独立的标题列，标题是立案问题截断出来的（切换栏也用它），于是导出的 Markdown 第一行会带一个省略号，紧接着的正文又印了完整问题。屏幕上是同一份，改的话两边一起改
- **证据索引里的锚点原样印库里那个值**（多数是校正后的行号，于是显示成 `锚点 2`）。补成"第 2 行"是在编一个 `anchor` 这个字段没有承诺的语义——它是任意字符串
- **修复建议没有写入方**：它是四栏里唯一"agent 真正生成"的那一块（[overview](overview.md) §6.1），而工具契约上还没有收它的字段，报告里恒为「无」
- **分布型的归因切分是按证据 `actor` 归的组**：schema 里没有真正的"切分维度"，于是影响面那一步的证据也会混进来成为一组。分布型的主体因此是五种里最弱的一块，真按它出过几份报告才知道要不要专门加一个切分 step
- **因果链的先后是排查先后，不是因果先后**：库里没有表达因果关系的字段（`parent_step_id` 说的是"在这一步之下细分"，不是"由它引起"），所以并行分支上的已证实结论仍会被串进同一条链。拿 `parent_step_id` 当因果用是在编一个数据里没有的东西，宁可不编
- **原生模块要按运行环境重建**：`better-sqlite3` 装完 electron 后只对一个 ABI 有效。**现在由 `npm run app` 与 `npm run spike:all` 各自切好**（同一天忘了两次，表现都是 app 停在启动失败屏上干等到超时，所以绑进脚本不靠记）。⚠️ 本机 npm 开了 `ignore-scripts`，**`npm rebuild` 会报成功但什么都没做**，回 node ABI 得 `cd node_modules/better-sqlite3 && npm run build-release`
- 对话带只存内存，不进库，刷新即丢
