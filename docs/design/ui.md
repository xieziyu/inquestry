## 1. 两个阶段，不是两个 tab

工具有两个形态完全不同的界面，分属两个屏：

| | 调查台（case 屏） | 报告（report 屏） |
| --- | --- | --- |
| 主角 | 假设与分叉 | 判定与证据 |
| 时间轴 | `observedAt` | 由形态决定，未必有 |
| 可操作 | 放行 / 改写 / 拒绝 / 接管 | 只有导出 |
| 刷新 | 每秒都在变 | 结案时冻结 |
| 失败的样子 | 拦不住、看不清在干嘛 | 看完还得问"所以是啥" |

两条时间线是同一批证据的两次投影，这是数据模型的事实，不该翻译成顶栏的两个 tab——排查线属于调查台，事故线属于报告。

**但两个屏共用同一套色板**——底色、语义色、字体完全一样。差别只来自密度与字号：调查台是拿来操作的，要密；报告是拿来读的，要疏。

| | 调查台 | 报告 |
| --- | --- | --- |
| 正文 | 13.5px / 1.6 | 15.5px / 1.72 |
| 判定大字 | — | 26px |
| 页边距 | 14px | 60px |
| 小节间距 | 12px | 44px |
| 底色 / 语义色 | 完全相同 | 完全相同 |

一深一浅会被读成两个应用，而这是同一个工具的两个阶段——报告里那句根因，和调查台里 ST3 的判定，本来就该是同一个东西。

## 2. 调查台：三区

```
┌ 顶栏  案件标题 · 状态计数 ·「N 项待你处理」· 计时/花费 · 接管 · 停止 ┐
│                                                                  │
│  轨道 344px      现场 flex               待办 328px               │
│  走到哪一步      这一步凭什么            哪些事卡在我这           │
│                                                                  │
└ 底栏  对话带（默认只露最后一句）+ 输入框 ──────────────────────────┘
```

**左·轨道**——主干纵向 + 分叉右生长，见 §3。
**中·现场**——当前 step 的假设 / 证伪条件 / 判定，工具调用的原始输出 preview（命中行高亮），以及抽取出的证据行。
**右·待办**——所有需要人动手的事，按紧迫性分三级，见 §4。

对话被压到底部一条带，默认只显示最后一句 assistant 文本。实跑下来看的确实是节点：agent 的文字里已经没有证据搬运，只剩判断，压缩掉不损失信息。

## 3. 轨道：主干永不重排

这是实时图唯一不可让步的约束。

> **主干严格纵向单调追加，永不重排；分叉只向右生长，分叉子树自己也遵守同一条约束。**

理由不是好看，是**新节点每几秒钻出来一个，任何"把图排漂亮"的布局算法都会让已有节点位移**——正读着第 3 个节点的证据，它跑了。代价是图越来越高而不是越来越宽，而纵向滚动本来就自然。

实现上是定宽画布内的绝对定位：主干 x 固定，分叉整体右移一个缩进量，新节点只能出现在下方或右侧的空白处。

**推翻关系用一条曲线回指**：被推翻的节点划掉并标「← 被 stX 推翻」，一条线从推翻它的节点弯回来。**全屏只有这一种曲线，它只表示推翻**——所以它一出现就不用读字也知道发生了什么。

上限约 40 个节点，再多要折叠。折叠规则待真实案子验证后再定。

## 4. 需要人的地方：按"不处理会怎样"分三级

不按工具类型分，因为工具类型不决定紧迫性。

| 级别 | 什么情况 | 不处理会怎样 | 提示强度 |
| --- | --- | --- | --- |
| ① 阻塞 | `ask_operator`：生产库、敏感数据、写操作 | 永远等下去。**这一档没有超时兜底**——自动填个假结果比等着更糟 | 实心暖色标头 + 顶栏计数 + dock 角标，永远置顶 |
| ② 限时 | `canUseTool` 闸门：范围过宽、动作可疑、方向不对 | 倒计时归零按预设放行，节点标记"自动放行"（§3.6） | 暖色描边 + 倒计时环，不抢焦点 |
| ③ 告知 | 只读类调用已自动放行 | 什么也不会发生 | 折叠成一行计数，中性色 |

**暖色是全局唯一的。** 界面里除了"需要人动手"，任何地方都不用暖色——余光扫过屏幕时，有没有事找你是一个颜色的有无，不需要读字。

**① 档四个字段的顺序是硬要求**：语句 → 预期 → 执行时间 → 结果。预期排在结果之前挡住事后合理化（D15）；执行时间不能省，它是这条证据进事故时间线的唯一凭据（§5.1②）。语句可改，改后连同结果一起回传给 agent。

**键盘要能全程处置**：`⌘↵` 提交回填 · `A` 放行 · `E` 改写 · `D` 拒绝并留话 · `J/K` 在待办间移动。切窗口执行 SQL 再切回来的成本已经很高，不该再加上找鼠标。

> 提交用 `⌘↵` 不是 `↵`：回填框要能粘多行结果，`↵` 得留给换行（与底部输入带同一个手势）。`J/K` 落到一张①档卡上时直接把光标放进结果框——切窗口跑完 SQL 回来，下一个动作一定是粘贴。代价是此时单字母键归输入框所有，要用 `A/E/D` 得先 `Esc` 或点开别处。

**① 档同时有多条时纵向排列共用一个提交动作**，不要逐条弹——批量问是提示词的事，批量答是界面的事（§5.1③）。

## 5. 视觉纪律

能查清问题排第一。下面是硬线。

| | |
| --- | --- |
| 底色是四阶冷灰蓝，**不用纯黑** | `#0E1317` 代码块 / `#141A1F` 应用底 / `#1A2128` 面板与顶栏 / `#212A32` 选中。纯黑上的白字会晕，长时间看更累 |
| 语义色只有三个 | 成立 `#5A9EDD`（蓝，主色） · 推翻 `#C9564C` · 需要人 `#E0A94A`。不加第四个 |
| 每个语义色两档 | 描边档给调查台，正文档（同色相亮一级，如 `#82B7E8`）给报告的大字。同一个颜色的两种用法，不是新颜色 |
| **蓝底不配黑字** | 深色界面里蓝色填充块必须配浅字：底压到 `#2A6598`、字用 `#F2F8FD`。琥珀是例外——它本身够亮，配深字 `#1A1206` 才对 |
| 色板全局一套 | 调查台与报告不分深浅两套，差别只能来自密度、字号、留白（§1） |
| 选中不用填色 | 用边框 + 极淡底色，填色会和语义色打架 |
| 对比度 | 正文对底 ≥ 7:1，次要 ≥ 4.5:1。语义色只做标记，不承载正文 |
| 正文字号 ≥ 13px | 节点里的假设句是要读的内容，不是标签 |
| 日志等宽 ≥ 11.5px | 再小要眯眼，而这是全屏最需要看清的东西 |
| 全大写小标签 9.5px | 只用于分区名与状态词，绝不用于内容 |
| 不加纹理与扫描线 | 和等宽字打架，长时间看很累 |
| 只有两处动效 | 进行中节点的状态呼吸、倒计时环。其余不动 |
| 直角、无投影 | 层次靠 1px 分隔线与底色深浅，密度更高 |
| 状态一律写字 | 不用图标——截图分享出去时图标会失去含义 |

密度分层：轨道密（扫视用，行高压紧）、现场疏（逐字读，给足行距）、待办居中（要一眼看到边界，用分隔带切开）。

## 6. 报告页

单列长页，**没有 tab、没有折叠、没有内部滚动**。

这不是审美偏好，是被长图导出倒逼的：**凡是要点击才能看到的内容，截图里就不存在**（§7.2）。顶部那条是锚点导航——点击只滚动，不隐藏任何东西，导出时整条移除。

章节由形态组装，见 [overview](overview.md) §6.1.1。每节右侧标注数据来源（`投影 · ORDER BY occurred_at_ms` / `agent 生成`），让"哪些是投影、哪些是生成"对读者可见——这把 D17 变成用户能验证的承诺。

被推翻的 step 强制留在「排查路径」里（划掉 + 标注），不洗成一路顺利的叙事。

**事故时间线画成真正的时间轴：一条竖线 + 圆点**，关键事件的点填实、其余空心。这和调查台轨道是同一个母题，只是两条线的含义不同——轨道上是"我按什么顺序做的"（`observedAt`），报告上是"系统当时按什么顺序发生的"（`occurredAt`）。同一个形承载两条线，正好是本工具最核心的那组区别（§1.4）。

竖线只在时间轴内部出现，与 §3 那条"全屏唯一的曲线表示推翻"不冲突：一个是直线连接、一个是曲线回指。

## 7. 两种导出，同一份章节组装逻辑

只是渲染目标不同。

### 7.1 Markdown

给会被继续编辑、被搜索、被贴进 PR 的场合。

- **根因用引用块置顶**——很多平台的预览只显示前几行，第一屏必须是结论本身
- **时间线用表格，不用 mermaid**——mermaid 在不少 wiki 和评论区不渲染，一旦不渲染就是一团噪音。mermaid 放进末尾 `<details>` 作为附加
- **证据用脚注**——正文只留 `[^e9]`，工具 / 锚点 / 时间戳来源统一落在文末索引，正文因此保持可读
- **被推翻的用删除线**——删掉就成了假历史
- **空的遗留疑点也要写**——写「无」比整节消失可信
- **除那个 `<details>` 外全篇纯 Markdown**，保证到处都能渲染
- 时间轴的竖线圆点画不进 Markdown，这里退化成表格——这也是长图存在的理由之一

### 7.2 长图

给一贴进群里就要被看懂的场合。它不是报告页的截图，是报告页的另一个渲染视图（`?export=image`），共用数据与样式，去掉一切交互件。

| | |
| --- | --- |
| 宽度 | 1240 CSS px，@2x 输出 2480px |
| 去掉 | 锚点导航、导出按钮、"展开全文"、任何 hover 才出现的东西 |
| 日志片段 | 只保留命中行 ±3 行并高亮；完整原文只在 app 与 Markdown 里给 |
| 页脚水印 | 每页固定：Case 编号 · 生成时间 ·「N 条证据可在 Inquestry 溯源」 |
| 分页 | 超过 6000 CSS px 按顶层小节切，**绝不从小节中间切断**，页眉带「Case 0417 · 2/3」 |
| 配色 | 与报告页一致，所见即所得。图片是这个工具的名片，不该长成另一副样子 |
| 不跟随系统主题 | 导出结果必须可预期：同一个 case 在谁的机器上导出都是同一张图 |

**打印是唯一的例外。** 深色页打印要么费墨要么被浏览器反色，由 `@media print` 单独处理——换纸不换设计语言。屏幕、图片、纸是三种介质，只有最后一种需要单独一套。

**单页优先。** 多数案子应该压得进一张图；分页是超长时的退路，不是默认形态。如果经常分三页，说明该收的是内容不是尺寸。

实现路径：离屏 `BrowserWindow({show:false, width:1240})` 载入导出视图 → 读 `scrollHeight` → `setContentSize` → `capturePage`。

> ⚠️ 必须等 `document.fonts.ready` 与一帧 `requestAnimationFrame` 再拍。`capturePage` 会返回过期帧，未获焦点的窗口尤其容易（§11 已踩过），不等就会拍到半成品。拍完比对图片高度与预期 `scrollHeight`，不符就重拍一次再报错——别默默产出半张图。

## 8. 案子的一生

前面几节只描述了"案子正在进行"这一个瞬间。日常用起来还要回答四件事。

### 8.1 立案

顺序是**先选项目起点，再写问题**：

- **项目起点**（本地路径）—— agent 在这个目录下运行，继承该项目的 skill 与 MCP 配置（[overview](overview.md) §2 "白送的能力"），会话记录也落在 `~/.claude/projects/<dir>` 的对应目录。给最近用过的路径做快捷入口
- **问题** —— 自由文本
- **事故基准日** —— 见下。时区不收，取本机的
- **已知线索**（可选）—— 涉及服务 / traceId / 用户 ID / 报错码。填了能省掉 agent 前几轮试探，不填也能跑
- **Agent / 模型 / 思考强度** —— 见下
- **权限模式初值** —— 分层放行（默认）/ 全程接管，随时可切

**Agent 三项落在 `sessions` 而不是 `cases` 上。** 一个案子跨多个会话（§4.1），中途换模型是常态——先用便宜的扫一遍，再换强的推。放 case 层会让"这一步是哪个模型跑的"永远答不上来，而报告里需要标出它。

| 项 | 说明 |
| --- | --- |
| backend | Claude（当前唯一实现）/ Codex（未接入，占位显示为禁用而不是隐藏） |
| model | 按 backend 列举，切 backend 时整个列表换掉 |
| effort | 思考强度。**不是所有 backend 都有**——走 D19 的能力协商，backend 不支持就整项隐藏，而不是给个假开关 |

> **模型列表是问出来的。** `query.supportedModels()` 返回每个模型的 `supportsEffort` 与可用档位——实测 Haiku 一档都没有，Opus / Sonnet / Fable 是 low→max 五档。写死一张表就一定会在这里给出拧了不生效的假开关。
>
> 代价是探测要 spawn 一次 CLI，所以：带超时、缓存进 `ui_settings`（24h）、问不到就退回内置表**并在面板上明说这是兜底**。backend 自己报的「默认」那一档直接当作"不指定模型"，不把 `default` 当模型名传下去。

> **基准日是硬需求，不是"可选线索"。**
> 日志时间串大多既没有日期也没有时区（`12:03:01.220`）。没有基准日，`occurred_at_ms` 落不成绝对时刻，事故时间线就排不出来（[data-model](data-model.md) §2）。它由立案面板收集并落 `cases`，同时**写进首轮提问的正文**——harness 与 agent 两边补齐时间串的基准必须是同一个，否则一条证据在库里和在报告里会落到两个时刻。
>
> 填错了不会报错，只会让事故时间线悄悄排乱。所以**提交前就校验**（日历上不存在的日子直接拦下），并且**常驻顶栏**，不是填完就消失。

**时区不给用户填，取立案机器的本机偏移并落库定死。** 让人手填一个 `±HH:MM` 是把一个几乎总是同一个值的东西做成了一个能填错的空——填错的后果是所有无时区证据整体偏移几小时，而且没有任何报错。取本机值同时也去掉了一整类校验（`+14:59` 这种格式合法但不存在的偏移）。

> ⚠️ 取的是**事故那一天**的偏移，不是此刻的。有夏令时的地区冬夏差一小时（实测 `America/New_York` 冬 `-05:00` 夏 `-04:00`、`Europe/Berlin` 冬 `+01:00` 夏 `+02:00`），冬天立一个夏天的案子就会把所有只有时分秒的证据整体挪一小时。面板上显示的偏移与落库的偏移必须来自同一个函数、同一个日期，各算各的迟早对不上。

**项目起点要在立案时就验**（存在、是目录、可读可进、绝对路径）。不验的话坏路径照样立案成功，要等点「开始排查」才由 SDK 抛错、会话直接 `crashed`，而那时它已经进了最近目录列表。校验失败要指明是哪个字段，面板才有地方显示。

> 代价要写明：**本工具因此假设「日志时区 = 立案机器时区」。** 排查异地部署的系统时这条会错，错法是整条事故时间线整体平移。真遇到了要加的是「按案子纠偏时区」的入口——纠偏必须留痕（走事件），因为它会改变一批已落库证据的时刻。

立案创建的是 **Case 不是 Session**——一次事故跨多会话（§4.1）。重开旧案时以库里那份立案单为准，本次不覆盖：基准日一旦变过，已落库的 `occurred_at_ms` 就对不上了。

**Session 要到真的跑第一轮时才开。** 立案与开会话时机不同，合在一起会让"打开 app 看一眼上次那个案子"每次都留下一条没有任何 turn 的空会话，越攒越多，还会污染"这一步是哪个模型跑的"。因此顶栏显示的 agent 三项取自 runner 手里的选择，不是 `sessions` 表——会话还没建时也得显示待会儿用哪个模型。

> 代价是**立案时选的 agent 一时无处可落**（`sessions` 还不存在），而"立完案先不跑、明天再说"是常态。所以它同时写进 `case_ui_state`，重开时按「上次跑用的 → 立案时选的 → 默认」取。少了这一步，重启后会静默换回默认模型，人选的那套连同顶栏显示一起消失。

**项目起点决定挂哪套工具**，不只是记录一个路径：填了就是真项目（`cwd` 指过去、加载该项目的磁盘 settings、直接给 Read/Grep/Glob 三件套），不填就是演示事故（隔离模式 + 内置玩具数据源）。把玩具数据源留在真项目里比没有它更糟——agent 会拿假订单日志当证据。

> `settingSources` 必须含 `project`，否则读不到该项目的 `CLAUDE.md`——「继承该项目的 skill 与 MCP」就只是句话，agent 会在缺项目约束的上下文里排查。演示模式反过来用隔离模式（`[]`），因为它要的是可复现。

> 🔴 **"放开的是上下文不是权限"这句话是错的，实测推翻。** 磁盘 settings 里的 `hooks` 是一串 shell 命令，**加载即执行**：在一个只有 `.claude/settings.json` 的空仓库上立案，`SessionStart` 与 `PreToolUse` 两个 hook 的命令都在宿主机上跑成了，没有任何提示，也不经过 `canUseTool` / `PreToolUse` / `disallowedTools`——`SessionStart` 甚至发生在第一次工具调用之前。项目 `.mcp.json` 里的 MCP server 同理，是直接拉起的进程。
>
> 所以三分法**只管得住 agent 自己发出的工具调用**，管不住仓库自带的配置。真正的信任边界是「你在立案面板里选的那个目录」，与在那个目录里直接跑 `claude` 等价。SDK 没有提供关掉磁盘 hooks 的开关（`managedSettings` 是限制性策略层，没有这一项），只有不加载那些 setting source 一条路；MCP 那一半可以用 `strictMcpConfig` 单独关掉。
>
> 这条对本工具尤其扎眼：**它被指向的仓库，正是"有什么东西不对"的那个**。已决定按"自己的仓库自己负责"接受该风险（单人自用，指的都是自己的仓库），备选缓解见 §12。

#### 工具面分三档，与§4 的三级同源

| 档 | 有哪些 | 怎么过 |
| --- | --- | --- |
| 直接放行 | 三个结构工具 · `ask_operator` · 记事本与工具检索 · 真项目下的 Read/Grep/Glob（演示模式换成玩具数据源） | 不记闸门，节点上不标 |
| 过闸门 | **其余一切**，数据源类 MCP、子 agent、联网都在内 | ②档待办，三分钟没人管就按预设放行 |
| 一律不给 | Bash / Write / Edit / NotebookEdit 这类跑命令与写盘的 | 同时进 `disallowedTools`，模型连看都看不到 |

第三档不走 `canUseTool` 一条路守：真项目会加载该项目自己的 settings，里面若有 allow 规则，闸门根本轮不到发言。

> ⚠️ 第三档挡的是 **agent 要不要跑命令**，不是「这台机器上不会有命令被跑」——仓库自带的 hook 照样会跑 shell，见下面那条红字。

> ⚠️ **实跑打出来的**：`canUseTool` 只在 backend 自己决定"要问"的时候才被调用。只读工具按默认模式直接放行，白名单压根没参与——第一次跑出来 `Read` 记着 `gate_decision='auto'` 就是这么来的。**每次调用都到的是 PreToolUse**，所以想拦谁必须在那儿回 `permissionDecision: 'ask'`，把它推到 `canUseTool` 上去。反过来，放行那一档要回空而不是回 `allow`：明写 allow 会盖掉项目自己的 deny 规则（比如不许读 `.env`），这里要的是别多管，不是抢权。

### 8.2 中途插话

四种方式，对应 §3 的三档控制语义：

| 方式 | 语义 | 落到哪 |
| --- | --- | --- |
| 底部输入带 | 异步入队，**不打断**（§3.3） | 轨道插入一个「补充」标记节点，可撤回 |
| 选中某个节点再说 | 同上，但消息带 step 引用 | 补充挂在那个节点下，比全局输入框精确得多 |
| 拒绝并留话 | `deny + message`，turn 不中断（D6） | 该调用记为"被拒"，留话进节点 |
| 改写参数后放行 | `allow + updatedInput` | 记 `input_rewritten`，改后的语句一起回传 |

后两条各有一个只在装起来之后才看得见的收尾：

- **被拒的调用不会有 `PostToolUse`**，不在拒绝那一刻补一次收尾，它就永远挂在 `pending` 上。留话原样落 blob——它就是 agent 收到的那份工具结果，节点上要看得见拒绝理由
- **判决落在哪条事件上取决于到达顺序**：`PreToolUse` 先到就补一条 `toolcall.gated`，闸门先落定就由 `toolcall.started` 直接带走。所以别去数 `gated` 的条数，要验就验重放后判决是否逐字一致（`npm run spike:gate`）

> ⚠️ **撤回有粒度坑**（§3.3）：多条排队消息合并成一个 turn 后，撤回非代表 uuid 是空操作，撤回批次代表 uuid 会丢整批，两种都报"未取消"。UI 要么不给批内单条撤回，要么明说"会连同这批一起撤回"。

### 8.3 并发多个案子

已实现，形状如下（`src/main/case-registry.ts` + `CaseBar`）。

- **案件切换栏**：顶栏下面一排 chip，进行中的排在前面（`ORDER BY (status='open') DESC, updated_at DESC`），各带一个徽标：等你 N（暖色）> 跑动中 > 已停 / 未打开 / 已结案。切换不中断任何一个——main 持有全部运行时，renderer 只切投影
- **待办计数跨 case 全局汇总**。并发场景里最容易漏掉的一条：你在 A 案上工作时，B 案卡在 `ask_operator` 上等你；只在当前 case 显示的话那条支线会静静挂死。落法是每个案子的 chip 自带「等你 N」，顶栏另有一颗描边的「别的案子 N」，点它直接跳过去
  - 汇总走 `todoCount` 这个便宜读数，**不走 `buildSnapshot`**：快照每 60ms 推一次，全量投影乘上案子数扛不住
- **活跃会话限流**（沿用 duetlens 的活跃会话 LRU）：`MAX_LIVE_CASES = 3`，限的是真的 spawn 了进程的那些（`sessionStatus === 'live'`），不是载入的案子数。超上限降级最久未交互的
  - ⚠️ **三种不能选：当前这个、正在跑的、挂着待办的。** 最后一条最容易漏——降级会把等着人回答的 pending 就地作废，等于替人做了「这条不查了」的决定，而 ①档故意没有超时兜底正是因为自动填个假结果比让人等着更糟。挑不出人选就让它超一个（软上限），拒绝新建或杀掉等人的支线都更糟
  - 降级要把运行时**从表里删干净**，不能留着一个已 `ended` 的：留着的话下次点开会往那个已收尾的 session 里接着写
- **重开旧案 = 新起一个 session**，`ordinal` 因此每个会话都从 1 重来，轨道上用「第 N 次会话」分隔线标出断点（只有一次会话时不标，那条线什么都没说明）
> ⚠️ **切换是同步生效的，界面慢一拍。** main 一收到 `case:switch` 当时就换了当前案子，
> renderer 要等下一次快照（最多 60ms）才换屏，这中间旧界面照样发得出调用。三条都得做到：
>
> - **凡是作用在当前案子上的 IPC 都要带 renderer 那一屏的 caseId**（`send` / `start` / `restart` /
>   `interrupt` / `answerOperator` / `decideGate`），main 用 `currentIf(caseId)` 核对，对不上就不执行。
>   ⚠️ **「按 id 查表，查不到就自然安全」是错的**：查不到 = **静默什么都不做**，而两档的后果都不是无事发生——
>   ①档是人贴进去的结果凭空消失、回填挂到超时；②档更重，人按了「拒绝」却没落地，三分钟后按预设**自动放行**
> - **两个处置手势要回执成功与否**，没落地要说出来（那时卡片多半已经不在屏幕上，提示得挂在应用级）
> - **人敲进去的东西一律提到 App 级**，按「caseId + 条目 id」存。卡片跟着快照渲染，一切案子就卸载，
>   局部 state 随之蒸发。清理**不能只靠处置回执**：闸门自动放行、回填超时、停止/重开散掉待办、runner 被回收
>   都会让卡片消失且没有回执，要拿当前快照的 id 对账（`renderer/drafts.ts`），且**只对账快照里那个案子**

- **历史**：entry 屏的 Case 列表 + FTS5 跨 case 检索。找旧案子的心智是"上次那个从库延迟的"，所以检索要能按根因形态 / 涉及服务 / 时间筛。中文查询串不足 3 字时回退 `LIKE`（[data-model](data-model.md) §5）。**尚未实现**，切换栏目前只列最近 20 个

### 8.4 三种收尾，不是一个按钮

与 §3「三档粒度不要混成一个 Stop 键」同源。

| 动作 | 对 agent | Case 状态 | 之后 |
| --- | --- | --- | --- |
| **停止** | 中断当前 turn，连排队消息一起清（D7） | `open` | 随时新开 session 接着查 |
| **结案** | 先走完影响面与遗留疑点两个强制 step（§6.2） | `closed` | 冻结，只能导出 |
| **归档** | 同"停止"，外加标记放弃 | `aborted` | 仍可导出**残报告** |

**提前终止不销毁任何证据**——与"结论可以被推翻，事实不会"（[data-model](data-model.md) §3）同一条原则。终止只做两件事：

1. 挂起中的 pending 一律改判 `abandoned`，否则库里会攒下永远 resolve 不了的僵尸节点（[data-model](data-model.md) §4）
2. 给 Case 打上状态

**残报告的形态强制为 `open`（未决型）**：主体是排除矩阵与遗留疑点，顶部明写"调查在第 N 步被人为终止"，**没有根因栏**。没查出来就是没查出来，不编——这比一份看起来完整实则半截的报告有用。

## 9. 全量快照推送，不做增量 diff

main 每次领域事件后重算整个 `Snapshot` 推给 renderer（60ms 合流）。

理由不是"数据小所以偷懒"，而是**增量 diff 的错法是静默的**：漏推一类节点，UI 上就是那类东西不存在，没有任何报错——duetlens 上「Discussion 栏整个为空却无人报错」正是这个形态。等数据量真的顶不住再换增量，那时至少有个能对照的正确实现。

## 10. 装起来才暴露的七个问题

前面四个 spike 全在 tsx 里跑，这些一个都不会出现：

| 问题 | 现象 | 结论 |
| --- | --- | --- |
| **ESM preload 需要 `sandbox: false`** | 窗口全黑、无任何报错 | Electron 只在关掉 sandbox 时加载 ESM preload，否则**静默失败**，`window.inquestry` 未定义、React 首个 effect 抛错整树卸载 |
| **schema 不幂等** | 第二次启动崩在 `table events already exists` | 全部 `CREATE ... IF NOT EXISTS` + `user_version`。投影可从 events 重放重建，所以迁移不必写数据搬运 |
| **case 每次启动都重开** | `UNIQUE constraint failed: cases.id` | 一次事故跨多会话（§4.1）：case 只开一次，每次启动是它下面的**新 session**。这条崩溃反而印证了 Case > Session 分层是对的 |
| **schema / 提示词用 `readFileSync` 读源码目录** | 开发期正常，打包必炸 | schema 改成 TS 常量；提示词由构建期 `?raw` 内联。两者都是启动必需品，这类失败只会在装机后才暴露 |
| **`canUseTool` 不是每次调用都到** | 白名单里没有 `Read`，它照样跑完，还记着 `gate_decision='auto'` | 只读工具按默认模式直接放行，backend 觉得不用问就不会问。**闸门的入口是 PreToolUse**，回 `permissionDecision: 'ask'` 才推得到 `canUseTool`（§8.1） |
| **一个 inbox 只能配一个 query** | 点「重开一轮会话」后库里有了新 session、界面显示进行中，agent 却什么都没收到，全程不报错 | `createInbox` 是 async generator，**只能有一个消费者**。`close()` 里必须换掉 `this.inbox`，否则开场白被正在收尾的旧查询取走，或旧迭代器一关、新查询直接看到 done。⚠️ 验这条**必须真去消费那个 generator**，只比较 inbox 引用是验不出来的 |
| **一轮失败 ≠ 会话结束** | 凭据过期后界面显示「会话中」，主区空白，输入框还能发但发不出去 | 消息流**不会自己结束**（实测 25s 后仍开着），`for await` 不返回，状态永远停在 `live`。只能靠 result 消息的 `is_error` 判断，⚠️ **`subtype` 那时仍是 `"success"`**，信它必错。判到之后要给一个显式的「重开一轮会话」——否则唯一的出路是重启 app |

renderer 的报错默认只留在它自己的 devtools 里——`console-message` / `did-fail-load` / `preload-error` 三个事件必须转发到 main 的 stdout，否则每次都只能盯着黑屏猜。

## 11. 开发期自检

无人值守跑一轮并截图，用于没人盯着屏幕时验证 UI：

```bash
INQUESTRY_AUTOSTART="<问题>" INQUESTRY_AUTO_OPERATOR=1 \
INQUESTRY_SHOT="a.png@25000,b.png@75000,c.png@150000" \
INQUESTRY_SHOT_INCIDENT=incident.png INQUESTRY_SHOT_QUIT=1 \
npx electron-vite preview
```

`INQUESTRY_AUTO_OPERATOR` 用数据源给的建议答案代替人回填，**同时把②档闸门一律放行**——不放的话跑到第一个闸门就停在那儿，而它三分钟后才自动放行，截图早拍完了。要拍闸门本身反过来别开这个开关。

> **它同时暴露了一个真实风险**：建议答案对不上问题时（拿订单行去答"索引是什么"），agent 当场识破并拒绝把结论算作已验证——与 tools.md §5 观测到的行为一致。

> ⚠️ 窗口未获焦点时 `capturePage()` 可能返回**过期帧**，截图看起来"停在几十秒前"。判断进度以库里的数据为准，不要以截图的时间戳为准。同一个坑在长图导出里必须显式规避（§7.2）。

## 12. 当前欠缺

- 🔴 **仓库自带的配置是被信任的**：真项目模式加载 `project` / `local` settings，其中的 `hooks` 加载即执行 shell、`.mcp.json` 直接拉起进程，三档工具面完全管不着（§8.1 有实测）。**已决定维持现状**：信任边界就是「你在立案面板里选的那个目录」，与在那儿直接跑 `claude` 等价——本工具是单人自用，指向的都是自己的仓库。要改的话，代价从小到大是：① 加 `strictMcpConfig` 堵住 MCP 那一半（hooks 照旧）；② 立案时加「信任这个仓库的配置」开关，默认隔离；③ 真项目也一律隔离，代价是 `CLAUDE.md` 与项目 skill 全丢，而那正是当初要它的理由
- **闸门只有三分钟一档**：`GATE_TIMEOUT_MS` 写死，既不能按工具分档，也不能"这次先别问了"。真跑几个案子才知道该不该加"本会话一直放行这个工具"
- **闸门判决不进事故时间线**：被拒的调用留在轨道上，但"人在几点拦了什么"目前只有 `tool_calls.started_at`，报告里讲不出这条线
- **立案单立完不可改**：基准日填错只能重新立案。顶栏常驻显示是为了让错误早点被看见，但改不了
- **收尾三档还没有动作**：`cases.status` 只有 schema 里的三档，没有写入方，也**没有对应的领域事件**——直接 `UPDATE cases` 的值一重放就没了。做那一步时状态变更必须走事件（overview §9.8.1）
- **旧案子只列不搜**：切换栏取最近 20 个（当前 / 跑着的 / 挂着待办的额外钉住，不被截掉），FTS5 跨 case 检索还没接上去（§8.3）
- **一轮失败之后会话不会自己收尾**：只给了「重开一轮会话」这个出口，没有区分「这次失败可以重试」与「这个会话已经废了」。凭据过期属于后者，但眼下两者走同一条路——重开会丢掉整轮上下文（§10）
- **时区只能是本机的**（§8.1）：排查异地系统的日志时整条事故时间线会平移，目前没有纠偏入口
- **开发期换 schema 会重建库**：旧库改名留着，但案子要重新造（[data-model](data-model.md) §2）
- **轨道还是平铺卡片流**，未实现 §3 的主干 + 分叉
- **报告页还未拆成独立屏**，两种导出均未实现
- **原生模块要按运行环境重建**：`npm run rebuild:electron` 给 app 用，tsx spike 要的是 node ABI；装完 electron 后 `better-sqlite3` 只对其中一个有效。⚠️ 本机 npm 开了 `ignore-scripts`，**`npm rebuild` 会报成功但什么都没做**，回 node ABI 得 `cd node_modules/better-sqlite3 && npm run build-release`
- 对话带只存内存，不进库，刷新即丢
