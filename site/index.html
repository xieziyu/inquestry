#03交回 等你处理

本机的只读查询它自己跑；生产库、敏感数据、写操作永远不给它直连——按后果分，不按工具分。

  • 琥珀是全屏唯一的暖色：余光扫过屏幕，有没有事找你是一个颜色的有无
  • 它必须先写下预期看到什么才能看结果，挡住事后合理化
  • 语句一键复制拿去自己那边跑，贴回来的结果照样进库，和它自己跑出来的证据同一等级

#05推翻 已证实

第 3 步的判断，经常被第 7 步否掉

真实调查就是这样走的。纯 append-only 的呈现会造出一条「一路顺利推导到真相」的假历史，而调查的价值恰恰在走错又折回的地方。

  • 全屏只有这一种曲线，它只表示推翻——不用读字也知道发生了什么
  • 结论可以被推翻，事实不会：被推翻的那一步连同它的证据强制留在报告里
  • 提前终止也不销毁任何证据

#06收口 已定稿

报告是投影，不是 agent 写的总结

每一块都有确定的数据来源，全从库里投影出来。它真正生成的只有未决型的「下一步怎么查」——报告与过程天然一致，改不了也编不了。

  • 系统时间线按事件真实发生时间重排，不让它凭记忆再写一遍
  • 中途被推翻的结论连同证据一起留在报告里
  • Markdown 与长图两种导出并列一等，共用同一份章节组装
