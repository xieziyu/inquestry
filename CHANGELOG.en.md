# Changelog

Only **user-visible** changes are recorded here. Internal refactors, docs and CI adjustments are not
listed — read `git log` for those. Versions follow [Semantic Versioning](https://semver.org/);
while on `0.x`, the minor position doubles as the breaking-change position.

## [0.4.0] - 2026-08-25

An older build no longer treats a library written by a newer one as a downgrade and moves it aside; plus a few fixes found while running a real investigation.

- **Older versions can open a library a newer version wrote.** Upgrading to 0.3.0 once looked like it had wiped every investigation. It had not: the 0.2.0 build still installed in `/Applications` was launched once against a library a newer build had already migrated to v9, decided it was a downgrade, archived it as `inquestry.db.v9.<stamp>.bak` and started empty — and the 0.3.0 update that landed a minute later happily adopted that empty library, so nothing ever pointed back at the archive. **Archiving is the wrong answer when only the reader is old**; the library is fine. `user_version` now records **the lowest reader a library still supports** rather than its version, and the real schema version moves to a `meta` table. Every migration step must declare itself `additive` (new tables, nullable or defaulted columns, indexes, new event types — the minimum reader does not move, so older builds keep opening the library and simply leave the new columns empty) or `breaking` (a changed CHECK, changed field semantics, or a new enum value on an existing column — it does). That last case is the easy one to miss: an old build has no branch for the new value, does not fail, and just draws those rows wrong. A library that really is too new is now **left untouched**: the app stops on the startup failure screen with a sentence explaining why, and that screen checks for updates and installs one on its own (the updater used to be built after the database opened, so a startup failure meant it was never constructed at all). Development and local `npm run package` builds also get their own userData directory instead of sharing a library with the installed app — that is how a development schema reached the release library in the first place. (#25)
- **Fixed: the case card kept the truncated fallback title.** The naming trip was not failing on the prompt — it was **timing out inside extended thinking**. On the same problem description it took 41s end to end with default adaptive thinking (39s of that spent thinking) versus 4.8s with thinking disabled, against a 30s timeout: the trip was always interrupted and collapsed into "could not ask", leaving the 40-character cut of the description's first line on the card, with nothing on screen saying the trip had run at all. This trip only compresses text that is already written, so thinking is now explicitly disabled. (#27)
- **Fixed: the detail drawer could not be scrolled.** The stage's wheel listener sat on the whole canvas and cancelled the default action unconditionally, and while the drawer and the todo layer are pinned to the viewport they are still DOM descendants of the canvas — so their native scrolling was eaten and the wheel panned the canvas instead. A wheel landing inside either layer now passes through; over a card it still pans, because cards do live on the canvas. (#27)
- **The tail card no longer reads as an arrived terminus.** While a report is open (whether or not it can be sealed) the tail card goes provisional: dashed border, most of the fill dropped so the dot grid shows through — reusing the existing "this card is not settled" idiom instead of giving the trunk connector a second meaning. Below about 30% zoom it reverts to a solid border and solid fill: at that scale the 1px gaps vanish, and an empty box becomes a hole. (#27)
- **Fixed: case lists ranked a just-sealed case below stale open ones.** The order was "open first, then most recent activity", so a case sealed minutes ago sat under open cases that had stopped days earlier — and the home track reads as a timeline, which made the axis lie about what happened when. Ordering is now purely by recent activity, shared by all three lists (recent, history, search hits). Keeping running cases visible does not depend on it: pinning, the "waiting on you" badge and the rail dot cover that. (#26)

**Upgrade notes**: the schema stays at v9 with no migration — the same database 0.3.0 uses. From this release, `user_version` holds the minimum reader (9) and the real version is recorded in the `meta` table. **Downgrading to 0.3.0 opens normally with every investigation intact**: the `user_version` it reads is exactly 9, matching its own version — which is the guarantee this release exists to make.

## [0.3.0] - 2026-08-21

A report can now hand over a list or a set of numbers, and the stage tightens into a trunk with its narration folded underneath.

- **Reports can carry a roster and metrics.** A whole class of investigation does not answer *why* — it answers *which*: find this user's sock puppets, which orders were double-charged, which change introduced this. The 16 linked userIds an investigation identified could previously only be written as prose in the verdict, interleaved with device fingerprints and registration dates; asking three times to "list the userIds" did not help, because there was no second place to write them. A roster now gets its own section right after the root cause and renders as a plain, copyable column, and metrics sit next to the prose that explains them in the impact section. Each has one field that cannot be omitted: a roster must say **whether it is the complete set**, a metric **whether it is only a lower bound** — that is the sentence deciding whether the reader dares to act on it. (#14)
- **Narration moves under the card it belongs to.** Aside lines used to live in a separate left column running on its own cursor, so with more than about two lines per step the column drifted further and further below the cards it described, and the tail card was pushed far away. Lines are now indented under their trunk card, consecutive ones fold into a group header (`N turns · preview of the first line`); clicking the header expands the group, clicking a line opens the full text on the right with a copy button. Groups default to folded, and the group of the running step carries a live marker. (#15, #22)
- **The "unclassified" card is gone.** Every investigation opened with a card titled 未归类 that carried no direction, no verdict and no evidence, and could never be closed because the agent never learns its id. The word was wrong too: it is not a classification failure but the "still looking, no hypothesis yet" phase. Its calls are real and must stay reachable, so they move onto the case card ("N further calls belong to no direction", click to list them); the report's investigation path drops the step entirely. (#19)
- **The minimap is collapsed by default, and the HUD no longer eats clicks.** The minimap was the only thing giving the HUD its height, and the HUD's whole box swallowed pointer events even where it looked like empty canvas: cards under that area could not be clicked and the canvas could not be dragged there. A 导览图 toggle now sits on the zoom bar; while collapsed the minimap is not rendered at all, the HUD shrinks from about 413x124 to 272x66, and the dead zone goes with it. (#18)
- **The operator statement is read-only with one-click copy.** This card's whole job is "take this statement somewhere else, run it, paste the result back", and it had no copy button while silently cutting the statement off at four rows. It is now a read-only block that scrolls instead of truncating. Editing is gone: a wrong table name has to come back inside the pasted result, which the `ask_operator` description and the prompt now state outright. Every letter shortcut on this card is gone and none replaced it; `⌘↵` remains the primary action of whichever card holds the keyboard. (#13)
- **Open reports keep "what to look at next"; resolved ones no longer give fix advice.** The investigating agent has no repair context — on a real case its plan was clearly weaker than the assessment of the agent that actually fixed the issue, and a confident-but-off plan only anchors the fixer, while the facts worth handing over (measured numbers, boundaries, constraints) already live in the evidence and the verdicts. What to observe next is the opposite: only the investigator can write it, so that half stays. This also fixes a selection bug — the old latest-wins rule let a leftover step's follow-up notes shadow the root-cause step's content and vice versa, with no error anywhere. (#12)
- **Exported files are named `case_<id>_<incident date>`.** The date is when the incident happened, not when you exported; the Markdown and the long image share the same name. (#11)
- **Fixed: evidence listed two or three times in the report's system timeline.** Re-closing a step re-inserted the whole evidence batch — one step on the dev database had been closed three times, turning 15 timeline rows into 32 and the evidence watermark from 37 into 63. A re-close now replaces the batch (an empty array means "only add next steps" and leaves the batch alone), and a close is all-or-nothing: one malformed `[call #N]` rejects the whole close and says so, instead of landing half a batch. Existing databases are corrected by this release's replay. (#16)
- **Fixed: evidence timestamps wrapped onto the claim text in the step sheet.** The time column was a hard-coded 82px while the agent may have written a full ISO stamp with offset (about 173px), so it wrapped to three lines and spilled 36px over the text. The column is now sized from its content with a cap, and dated stamps render as `MM-DD HH:mm:ss` in the case's base timezone with the raw string kept in the tooltip. Anything that cannot be read back exactly — time-only stamps, non-ISO shapes, impossible days such as Feb 30 — stays as the agent wrote it. The report timeline and the Markdown export are unchanged on purpose: they are documents handed to someone else, who is not necessarily in the same timezone. (#23)
- **Fixed: a tool call's output and its status now land together.** They used to be two commits; if the second failed, the output was already in the database while the call stayed pending, and the next sweep marked it abandoned with a placeholder, leaving the real output as a blob nothing points to. (#17)

**Upgrade notes**: the schema migrates from v7 to v9 by replay, so your investigations stay in place. The v9 step re-projects evidence under the new rule, which also clears the duplicates in existing databases (not a byte of the events is touched). **Downgrading to 0.2.0 cannot read this database**: a version newer than the code can only be moved aside, so the old file is renamed to `<db>.v9.<timestamp>.bak` and the app creates an empty one — after a downgrade you see a UI with no investigations at all. The records are still on disk, but only 0.3.0 can read them.

## [0.2.0] - 2026-08-20

A newly created investigation now starts on its own, and you can see what it is doing right now.

- **A new investigation runs its first turn by itself.** It used to sit on the trunk card doing nothing — the composer button is the only entry to a session and it is disabled while the input is empty, and nothing on screen said what was being waited for. Creating a case now starts the first turn; if that turn cannot start, it says so (banner plus a crashed session), and your draft stays in the composer instead of being queued behind a busy flag nobody reads. (#1)
- **A link in the description no longer forces the fallback title.** The title probe now gets no tools at all: it reads only the text you wrote, and never reaches for what a link or a file holds — that is the investigation's job. It previously kept one tool entry open, so a model that saw a link tried to fetch, spent the probe's single turn on it, and the title silently stayed on the fallback with nothing on screen saying the probe had failed. When the description is short enough to be just a link, the title now carries whatever identifier it can recognise (issue number, traceId, service name, user id). (#9)
- **See what is happening right now.** A running step card carries a heartbeat strip (tool name, elapsed time, call and evidence counts), every running sub-agent gets a chip on its lane head, and the HUD shows the last update. Seconds are ticked by the renderer rather than by snapshots — a 90s tool call pushes nothing at all on its own. (#2)
- **Operator backfills can be declined.** The backfill card gains a "don't run" gesture: you can hand a statement back when you have no access either, or when it should not run in production, with the reason optional. The agent receives an explicit refusal — it will not treat it as "queried, no rows" and reason on from there, nor send the same statement again — and the call is recorded on the track as denied rather than done. (#4)
- **Everything pending is collected when a session breaks off.** A stream break or crash used to collect only lanes, leaving pending backfills, pending gates and in-flight tool calls where they were: a call showed as running until the next launch, and report call counts ran high with it. (#3)
- **Lane narration only says what the track cannot show.** A lane that finished with a conclusion is no longer read out again in the chat strip — that sentence is already on the card; narration is kept for the lane that made no calls at all and therefore never appears on the track. (#5)
- **Calmer report layout.** The root cause is set as ordinary body prose instead of a wall of enlarged bold text, and the paper stamp is reduced to a small tag. The layout no longer guesses which words matter. (#7, #8)
- **Fixed: the grab cursor on the stage leaked onto selectable text.** (#6)

**Upgrade notes**: no database migration in this release — the schema stays at v7, the same database 0.1.1 uses. Downgrading back to 0.1.1 opens it as usual: a declined backfill is stored as a `denied` call, which the older version already understands; it just has no "don't run" gesture in the UI.

## [0.1.1] - 2026-08-19

Fixes 0.1.0 not being able to reach Claude at all.

- **Fixed: investigations could not start in the released build.** The CLI the agent runs was packed inside the asar archive and could not be spawned (`spawn ENOTDIR`). It showed up as an empty backend and model list in the new-investigation panel, and nothing happening on "start". Only the packaged app was affected; running from source was not.
- **Claude Code no longer has to be installed.** The app ships its own CLI; all it needs is a logged-in Claude account (the first login still happens in a terminal via `claude auth login`). The About section now shows the login state and account, and the environment warning says that instead of "claude executable not found".

## [0.1.0] - 2026-08-16

First public release.

- **Full evidence retention**: the harness persists the raw input/output of every tool call the agent makes; the agent's prose only indexes and judges. Reviewing an investigation relies on the evidence itself, not on re-running.
- **Timeline as control plane**: watch the investigation live and act on nodes directly — approve / rewrite / deny / take over / stop; `ask_operator` hands credential-requiring or high-consequence operations back to you, and forces the agent to state its expectation before seeing the result.
- **Two timelines**: the investigation timeline follows the agent's order of actions; the system timeline reorders by when events actually occurred — two projections of the same evidence.
- **Conclusions can be overturned**: overturned conclusions stay in the report together with their evidence; no fabricated straight-line history.
- **The report is a projection**: sections are projected from the database and agree with the process by construction; Markdown and long-image exports.
- **Retrieval by investigation**: one investigation spans multiple sessions; everything lives in local SQLite, with large payloads stored content-addressed on disk.
- **Runs on your Claude subscription**: spawns the local `claude` CLI and inherits its login credentials; your existing skills and MCP configs load as usual.
- **In-app auto-update**: downloads in the background and installs on quit; the settings screen shows status and offers an immediate restart.
